# Interoperability qualification

Work from the repository root. Resolve instruction paths from that root. Read `AGENTS.md`, the interoperability index (`test/interoperability/README.md`) and only the selected harness guide below. Preserve investigation-only and unit-only scope. A peer is compatibility evidence, not normative authority. Establish the exact source/profile/tool revision and requested local execution boundary before acquiring or running it.

## Preserve independent controls and ownership

For independent client/consumer tools, use each guide's separate installation target when acquisition is within the requested scope. Their execution uses locked installed tools and cached application inputs; missing/stale prerequisites fail rather than silently download or substitute a global client.

The retained-lab Directory target requires an explicitly selected existing lab and does not provision it. The separate Minikube target creates its own single-node Calico profile with exact installed pins, native local schema validation, private HTTPS, current Catalog images and healthy network-denial controls. Use the shared Minikube prerequisites and preserve its selected native/Catalog qualification scope and peer limitations. The two-Catalog Compose target instead rebuilds owned images and starts separate real PostgreSQL instances; follow its normal build/Compose prerequisites rather than describe it as offline or memory-only.

Use `gh` exclusively for GitHub acquisition. Keep pins/notices and tool closures separate from application dependencies; dependency maintenance (`.agents/skills/dependency-maintenance/SKILL.md`) owns updates. Preserve the Plugin reader's recorded proprietary transitive dependency and redistribution limitation.

For governed client/package handoffs, establish native direct success and meaningful failure controls first. Bind CLI-selected published release, immutable revisions, retained profile/evidence and exact bytes/digests or file inventory; a later unpublished draft must not alter the selection. Denied required Catalog reads create no handoff or native call. Keep independently public archive access distinct from denied private metadata. Runtime failures must leave Catalog evidence intact and fail for the intended TLS, credential or availability cause, not container startup or unrelated errors.

Catalog-to-Catalog scenarios instead assert the selected source/snapshot membership, provenance, audience, complete/partial outcomes and lifecycle/recovery phases required by their owning guide; they do not need an invented client invocation.

Preserve the selected harness's private trust, fixed loopback/internal endpoints, bounded work and network isolation. Synthetic Catalog credentials must not enter ordinary runtime consumer configuration; keep intentional credential-negative controls explicit and isolated. Ordinary metadata phases must not cause invocation, arbitrary artifact fetches or public traffic. Do not patch the peer, translate its responses or weaken Catalog admission to manufacture compatibility. Use standards conformance (`.agents/skills/standards-conformance/SKILL.md`) to classify mismatches against the pinned specification, and security review (`.agents/skills/security-review/SKILL.md`) for substantive trust-boundary changes.

## Interpret, verify and record

Run environment-owning scenarios sequentially and leave retained deployments, other containers and the selected Directory seed intact. Use invocation-owned cleanup and interruption checks under the owning guide. Reports must bind source/tool/binary identities, complete native outcomes and phase observations; exit zero, a missing schema validator or incomplete cleanup is not successful qualification. Keep native failures separate from a passing characterization of a documented client limitation.

Ordinary helper units must not import or execute independent tools. Use unit testing (`.agents/skills/unit-testing/SKILL.md`) and functional testing (`.agents/skills/functional-testing/SKILL.md`) for existing helper/process assertions, then the selected real target after harness or pin changes. Coordinate applicable lint/regression gates through post-code verification (`.agents/skills/post-code-verification/SKILL.md`). Scenario outcomes are not statement-coverage percentages or certification of the full protocol.

Record confirmed Catalog defects separately from peer limitations, fixture/tool failures and environment problems. Fix Catalog defects only within authorized implementation scope, retaining minimized regressions and rerunning the affected real target. Keep redacted raw evidence under ignored `output/`. Reviewed findings may use the optional private records described in `AGENTS.md`. Update a todo only for unresolved actionable work. Report supported behavior, capability limits, actual qualification and cleanup independently.
