This tutorial connects two independent Catalogs. A publishes an Agent; B synchronizes its published metadata and retains external provenance. This [federation](../reference/glossary.md#federation) does not copy databases, drafts, users, passwords or access policy. Discovery does not install or execute the Agent.

<FederationPeers />

The baseline uses indexed synchronization only. B initiates HTTPS requests to A; metadata flows from A to B. Live queries, referrals, reciprocal federation and local adoption remain explicit follow-ups.

Keep the same shell, private `CATALOG_TUTORIAL_DIRECTORY`, CA, Compose project and account subjects. The [complete local recipe](../../../../../examples/tutorials/local-oidc/README.md) prepares both Catalogs before either starts; no test target is an interactive launcher.

Reuse [the project-pinned `tutorial_compose` helper](../operations/oidc-keycloak.md#select-the-prepared-project-and-start-dependencies) for every Compose operation below. It invokes the checked-in launcher, reads the selected generated metadata and supplies `--project-name` explicitly. Confirm its `--show-project` result before cleanup; ambient project/interpolation settings cannot replace the prepared inputs. If preparation failed or the seven-day certificates expired, follow [preparation recovery](../operations/oidc-keycloak.md#recover-from-failed-preparation) or [certificate recovery](../operations/oidc-keycloak.md#replace-expired-tutorial-certificates) before continuing. A fresh project requires fresh accounts, grants, logins and source credentials; it does not migrate this tutorial's retained state.

The prerequisite setup supplies Docker/Compose, Python 3.12-3.14, OpenSSL, curl, Make, Go, images, a browser and the PostgreSQL 18 client inside the selected database image. For source-built VSIX acquisition, also prepare [Git](https://git-scm.com/downloads), configured [GitHub CLI](https://cli.github.com/) and the supported Linux amd64 desktop. The SDK installer supplies pinned Node/npm; no global Node installation is required. Downloads need network/disk capacity; the complete stack's minimum RAM requirement has not been measured.

Preserve the host/browser/editor name mapping and certificate trust from Keycloak setup. The curl helper below resolves only the two tutorial API origins to loopback while retaining their TLS names. Inside Compose, B resolves A to the private TLS frontend, normally `172.29.245.10`. It never uses a loopback fetch exception.

Before B starts, inspect its prepared inputs:

- `http.publicBaseUrl` is `https://catalog-b.test:8445`; `discovery.hosts` contains B's exact hostname, tenant, authenticated audience and publisher domain.
- `b/federation-policy.json` defines private profile `tutorial-a`, exact origin `https://catalog-a.test:8443`, the selected frontend `/32`, B's tenant assignment and `/trust/ca.pem`.
- API and worker mount the same policy/CA and `b/source-credentials/` at `/credentials`, with `credentialResolution.enabled: true` and that directory selected.
- A/B have separate PostgreSQL owner/API/worker identities, DSNs, cursor keys, UI client secrets and UI cookie-key rings. Only runtime API/worker roles receive their own cursor key.

These static inputs load at startup. Credential generations are added later to the already mounted directory. Changing policy/resolver/trust startup settings requires recreating the selected API/worker processes. Replacing a supported credential generation does not.

## Keep actors, files and requests separate

Use separate browser profiles for each human login. Verify **My access** after each handoff; issuer SSO can otherwise select the previous account.

| Responsibility | Selected credential | Authority |
| --- | --- | --- |
| Database/operator setup | Owned `owner-a` / `owner-b` services | Dedicated schema-owner DSN, migration and initial administrator provisioning |
| A administrator/publication administrator | `a/admin-login.json`, derived `a/admin.headers` | Tenant administration, Publisher/domain setup and explicit tenant Publication administrator assignment |
| A author/release Publisher | `a/author-login.json`, derived `a/author.headers` | Contributor and Publisher in the tutorial namespace |
| A independent Reviewer | `a/reviewer-login.json`, derived `a/reviewer.headers` | Reviewer in that same namespace; a different subject from the author |
| A ordinary Reader | `a/reader-login.json`, derived `a/reader.headers` | Reader; local release access, not source administration |
| B administrator acting as Source Administrator | `b/admin-login.json`, derived `b/admin.headers` | Source inspection, management, synchronization, retained reads and Job reads |
| B ordinary Reader | `b/reader-login.json`, derived `b/reader.headers` | Reader plus tenant Discovery reader |
| B's upstream caller on A | `catalog-source-b-to-a` service identity | Service membership plus tenant Discovery reader on A; no human UI session |

The main Keycloak walkthrough sets `auth.enforceScopes: false`; signature/issuer/audience verification and Catalog permissions remain enforced. If you enable [OAuth scope ceilings](../operations/oidc-keycloak.md#enable-oauth-scope-enforcement), request the corresponding scopes before deriving header files. Reads require `catalog.read`; authoring uses `catalog.write`, decisions `catalog.review`, releases/snapshots `catalog.publish`, access administration `tenant.admin`, and Publisher commands `publishers.manage`. Source commands use `sources.manage`; retained source/evidence reads use `sources.read`.

B's Source Administrator needs tenant `source.inspect`, `source.manage`, `source.sync`, `source.read`, `source.read_evidence` and `job.read`. B's external Control Search requires `federation.discover`. A's authenticated manifest requires tenant `discovery.read`. Scopes limit these permissions; they do not grant them.

### Capture bodies, IDs and ETags

Run these definitions in one Bash shell from the repository root. They keep private responses outside the checkout and never place bearer tokens in command arguments. Expected statuses come from the HTTP contract; an unexpected status stops the step.

```sh
set -eu
umask 077
export CATALOG_TUTORIAL_CA="$CATALOG_TUTORIAL_DIRECTORY/trust/ca.pem"
export A_ORIGIN=https://catalog-a.test:8443
export B_ORIGIN=https://catalog-b.test:8445
export FEDERATION_RUN_ID=$(python3 -c 'import uuid; print(uuid.uuid4().hex)')
export FEDERATION_RESULTS="$CATALOG_TUTORIAL_DIRECTORY/federation-$FEDERATION_RUN_ID"
mkdir -m 700 "$FEDERATION_RESULTS"
printf '{}\n' > "$FEDERATION_RESULTS/empty.json"

jget() {
  python3 - "$1" "$2" <<'PY'
import json, sys
value = json.load(open(sys.argv[1]))
for part in sys.argv[2].split("."):
    value = value[int(part)] if isinstance(value, list) else value[part]
print(value)
PY
}
field() { jget "$FEDERATION_RESULTS/$1.json" "$2"; }
etag() {
  python3 - "$FEDERATION_RESULTS/$1.headers" <<'PY'
import sys
values = [line.split(":", 1)[1].strip() for line in open(sys.argv[1])
          if line.lower().startswith("etag:")]
if not values:
    raise SystemExit("The response has no ETag")
print(values[-1])
PY
}
api() {
  # name, method, private header file, origin, path, body file, ETag, status
  local response_name="$1" method="$2" header_file="$3" origin="$4"
  local route="$5" body_file="$6" revision_etag="$7" expected="$8"
  local resolve_name response_status
  case "$origin" in
    "$A_ORIGIN") resolve_name=catalog-a.test:8443:127.0.0.1 ;;
    "$B_ORIGIN") resolve_name=catalog-b.test:8445:127.0.0.1 ;;
    *) printf 'Select one tutorial API origin.\n' >&2; return 1 ;;
  esac
  set -- curl --silent --show-error --connect-timeout 5 --max-time 30 \
    --noproxy '*' --proto '=https' --resolve "$resolve_name" \
    --cacert "$CATALOG_TUTORIAL_CA" --header @"$header_file" \
    --request "$method" --dump-header "$FEDERATION_RESULTS/$response_name.headers" \
    --output "$FEDERATION_RESULTS/$response_name.json" --write-out '%{http_code}'
  if test -n "$body_file"; then
    set -- "$@" --header 'Content-Type: application/json' --data-binary @"$body_file"
  fi
  if test "$method" != GET && test "$route" != /api/v1/catalog/search; then
    set -- "$@" --header "Idempotency-Key: $FEDERATION_RUN_ID-$response_name"
  fi
  if test -n "$revision_etag"; then
    set -- "$@" --header "If-Match: $revision_etag"
  fi
  response_status=$("$@" "$origin$route")
  printf '%s: HTTP %s\n' "$response_name" "$response_status"
  test "$response_status" = "$expected"
}
```

For a new mutation, use a new response name/key. For an uncertain outcome, retain its exact name, body, original ETag and actor before deliberate replay. Do not rerun a changed request under the same key.

Credentials expire. Try a supported `remote --login-file` read for configured refresh. If fresh login is required, log out that actor's selected file first; for A's administrator, use `catalogctl auth logout --file "$CATALOG_TUTORIAL_DIRECTORY/a/admin-login.json"`. Repeat the same actor's login and [recreate derived headers](../operations/oidc-keycloak.md#prepare-private-http-credentials). Keep an uncertain command's original actor, name, body and ETag unchanged.

### Publish one complete credential generation on B

The binding belongs to B's consuming tenant and A's exact origin. Write a new immutable token file first. Then atomically replace `catalog-a-reader.json`. Use a new revision and token filename for every replacement. Do not reuse either.

```sh
project_source_token() {
  python3 - "$CATALOG_TUTORIAL_DIRECTORY/b" <<'PY'
import datetime, json, os, tempfile, uuid
from pathlib import Path
root = Path(__import__("sys").argv[1])
claims = json.loads((root / "upstream-a.claims.json").read_text())
expiry = datetime.datetime.fromisoformat(claims["expiresAt"])
assert expiry > datetime.datetime.now(datetime.timezone.utc)
token = (root / "upstream-a.token").read_text()
directory = root / "source-credentials"
revision = "source-a-" + uuid.uuid4().hex
leaf = revision + ".token"
descriptor = os.open(directory / leaf, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(descriptor, "w") as stream:
    stream.write(token)
    stream.flush()
    os.fsync(stream.fileno())
    os.fchmod(stream.fileno(), 0o444)
metadata = {"schemaVersion": 1,
            "tenantId": "00000000-0000-7000-8000-000000000002",
            "revision": revision, "expiresAt": claims["expiresAt"],
            "origin": "https://catalog-a.test:8443", "type": "bearer", "secretFile": leaf}
descriptor, staging = tempfile.mkstemp(prefix=".generation-", dir=directory)
try:
    with os.fdopen(descriptor, "w") as stream:
        json.dump(metadata, stream)
        stream.flush()
        os.fsync(stream.fileno())
        os.fchmod(stream.fileno(), 0o444)
    os.replace(staging, directory / "catalog-a-reader.json")
finally:
    if os.path.exists(staging):
        os.unlink(staging)
print(revision)
PY
}
SOURCE_CREDENTIAL_REVISION=$(project_source_token)
```

The host's owning `0700` tutorial directory protects these files. The mounted credential directory is `0755` and its immutable token files are `0444` so the non-root API/worker can read their scoped read-only mount. Neither the UI nor an external peer receives this directory. Do not expose it through a web server or copy it into reports.

Changing token, expiry, origin, tenant or type without a new revision violates the resolver contract. Old token files remain until no in-flight request can use that generation; this disposable tutorial removes them only during complete cleanup. Catalog does not acquire or refresh source tokens. External operators own this replacement process.

### Check that the Job succeeded and the source snapshot is complete

Define one bounded helper for the initial sync and later repeats. It never retries a mutation automatically. It polls the returned Job for up to 180 seconds, with individual HTTP reads bounded by 30 seconds. An in-flight final read can finish after the poll budget.

```sh
complete_sync() {
  local prefix="$1" source_revision deadline job_state=queued
  api "$prefix-source" GET "$CATALOG_TUTORIAL_DIRECTORY/b/admin.headers" "$B_ORIGIN" \
    "/api/v1/federation/sources/$SOURCE_ID" '' '' 200
  source_revision=$(field "$prefix-source" revision)
  api "$prefix" POST "$CATALOG_TUTORIAL_DIRECTORY/b/admin.headers" "$B_ORIGIN" \
    "/api/v1/federation/sources/$SOURCE_ID:sync" "$FEDERATION_RESULTS/empty.json" \
    "$(etag "$prefix-source")" 202
  SYNC_JOB_ID=$(field "$prefix" job.id)
  deadline=$(( $(date +%s) + 180 ))
  while test "$(date +%s)" -lt "$deadline"; do
    api "$prefix-job" GET "$CATALOG_TUTORIAL_DIRECTORY/b/admin.headers" "$B_ORIGIN" \
      "/api/v1/jobs/$SYNC_JOB_ID" '' '' 200
    job_state=$(field "$prefix-job" state)
    case "$job_state" in
      succeeded) break ;;
      failed|cancelled|dead_letter) printf 'Inspect the unsuccessful Job.\n' >&2; return 1 ;;
    esac
    sleep 2
  done
  test "$job_state" = succeeded
  test "$(field "$prefix-job" result.type)" = source_snapshot
  test "$(field "$prefix-job" result.state)" = complete
  test "$(field "$prefix-job" result.sourceId)" = "$SOURCE_ID"
  SYNC_SNAPSHOT_ID=$(field "$prefix-job" result.snapshotId)
  api "$prefix-snapshot" GET "$CATALOG_TUTORIAL_DIRECTORY/b/admin.headers" "$B_ORIGIN" \
    "/api/v1/federation/snapshots/$SYNC_SNAPSHOT_ID" '' '' 200
  api "$prefix-current-source" GET "$CATALOG_TUTORIAL_DIRECTORY/b/admin.headers" "$B_ORIGIN" \
    "/api/v1/federation/sources/$SOURCE_ID" '' '' 200
  python3 - "$FEDERATION_RESULTS/$prefix-snapshot.json" "$FEDERATION_RESULTS/$prefix-current-source.json" \
    "$SOURCE_ID" "$source_revision" "$SYNC_SNAPSHOT_ID" <<'PY'
import json, sys
snapshot, source = (json.load(open(p)) for p in sys.argv[1:3])
assert snapshot["state"] == "complete" and snapshot["enumerationComplete"] is True
assert snapshot["sourceId"] == sys.argv[3] and snapshot["sourceRevision"] == int(sys.argv[4])
assert source["lastCompleteSnapshotId"] == sys.argv[5]
PY
}
complete_sync sync-initial
LAST_COMPLETE_SNAPSHOT_ID=$SYNC_SNAPSHOT_ID
```

`POST :sync` returns `{job, existing}`; `GET /jobs/{id}` returns a bare Job. Success can still retain an incomplete source snapshot, so all checks above matter. The exact snapshot must be complete, enumerate completely, match the source/revision and be the source's last complete snapshot. Inspect retained entry/change counts, findings and withdrawal authority too; Registry List completeness alone does not prove upstream deletion authority.

If the helper stops, preserve the Job ID and inspect its current state. `queued`, `running` and `waiting` are not completion. Repair the demonstrated dependency/configuration problem before a new explicit sync; do not label a timeout or partial result a pass.

```sh
    cancelled) printf 'The outage Job was cancelled; investigate before proceeding.\n' >&2; exit 1 ;;
  esac
  sleep 2
done
test "$outage_state" != queued && test "$outage_state" != running
api outage-retained-source GET "$CATALOG_TUTORIAL_DIRECTORY/b/admin.headers" "$B_ORIGIN" \
  "/api/v1/federation/sources/$SOURCE_ID" '' '' 200
test "$(field outage-retained-source lastCompleteSnapshotId)" = "$LAST_COMPLETE_SNAPSHOT_ID"
api outage-indexed POST "$CATALOG_TUTORIAL_DIRECTORY/b/reader.headers" "$B_ORIGIN" \
  /api/v1/catalog/search "$FEDERATION_RESULTS/indexed-query.json" '' 200
python3 - "$FEDERATION_RESULTS/outage-indexed.json" "$TUTORIAL_IDENTIFIER" <<'PY'
import json, sys
assert any(i["identifier"] == sys.argv[2] and i["type"] == "indexed"
           for i in json.load(open(sys.argv[1]))["items"])
PY
tutorial_compose up -d --wait api-a
complete_sync sync-recovery
LAST_COMPLETE_SNAPSHOT_ID=$SYNC_SNAPSHOT_ID
```

Inspect the actual outage Job's `state`, `attempt`, `attemptLimit`, `notBefore` and safe failure classification. A retryable outage can leave it `waiting`; do not call that terminal failure. The 180-second reader poll is not the worker's retry budget. A successful Job with a non-complete snapshot is also an unsuccessful synchronization. Restarting A can allow retained waiting work to finish; a new explicit sync can coalesce with existing work.

Failed/incomplete synchronization preserves the last complete membership. Eligible indexed observations remain searchable from active/error sources. `lastSyncAt` and observation `lastSeenAt` show age; age alone does not expire them. Replacing egress policy does not itself withdraw observations. Pausing, scope changes, current access and complete reconciliation have their separate participation effects.

## Optional next steps and limits

- **Compare origins:** Local-only B Search is empty until B has its own released resource. Indexed-only can show an external counterpart even when B has a local copy. Combined Local+Indexed can prefer local identity. Local facets never count B's external observations.
- **Adopt deliberately:** [Adoption](../operations/federation.mdx#adopt-one-observation-as-a-local-draft) selects exact observation/snapshot/occurrence evidence and an authorized B destination. It creates a draft, not approval or installation. Release it through B's own independent workflow before calling it local.
- **Enable live/referrals:** Follow [participation policy](../operations/federation.mdx#choose-indexed-live-and-referral-participation), with inspected Registry Search, exact host/audience assignments and query-disclosure acknowledgement. Nonblank live queries are bounded; a referral locator alone grants no network authority.
- **Configure B to A reciprocally:** Inspect/register B as a separate source on A. A's default public policy is disabled; prepare its exact private route/trust/credential resolver and recreate A runtimes before that optional workflow. Do not reuse the A-directed token or bypass outbound policy.
- **Add other resource kinds:** Use supported, tested delivery forms and their own review/publication. Curated package-only Skills are excluded from ARD/AI Catalog snapshots with `PUBLIC_DELIVERY_FORM_REQUIRED`, including authenticated snapshots. `make demo-up`/`demoArchives` are development inputs and do not load this OIDC Catalog.

The [search cookbook](search-cookbook.mdx) covers local/indexed comparisons and separately prepared optional live/hybrid cases.
