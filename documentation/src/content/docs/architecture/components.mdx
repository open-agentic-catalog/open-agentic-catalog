The backend and UI Go host share the root Go module. Separate test-tool modules and SDK packages keep their dependencies outside the service module. The Go, Python, TypeScript and Rust SDKs generate clients from Control OpenAPI. The service and CLI build independently of the SDKs. See the [SDK overview](../../../../../sdk/README.md) and [test placement and selection](../contributing/testing.md#test-placement-and-selection) for package boundaries and checks.

## Read the code in four layers

### Commands compose; they do not decide

`cmd/catalogd` selects a process role and supervises shutdown. `cmd/catalogctl` previews native manifests and reusable JSON drafts locally, then applies or resumes drafts through the API. It exports native documents or reusable JSON files and provides read-only MCP tools, remote reads and explicit reindex/assessment requests. It also exposes bounded operator actions.

API client workflows use an explicit origin and credentials without composing the service or opening PostgreSQL. Remote commands and online import/export can use an explicit human login file with serialized token refresh. MCP stdio uses its separately configured bearer credential. `internal/platform/runtime` composes services, stores, fetch policy, workers and HTTP dependencies. See the [command reference](../reference/commands.md) for each workflow's inputs and authority.

### Domain packages own lifecycle rules

`catalog`, `identity`, `ratings`, `feedback`, `personal`, `federation`, `publication`, `tenantsettings`, `jobs`, and `webhook` own canonical types, state transitions, safe errors, and the narrow ports their behavior requires. `personal` owns private saved-reference/search commands and bounded owner-only stores; it grants no authority over a saved target. Catalog owns the separately derived My work projection.

### Translate protocols into use cases

`internal/platform/httpserver` owns routing, middleware, strict decoding, authentication handoff, response encoding, and HTTP errors. It calls domain services; it does not invent lifecycle or persistence rules.

`internal/platform/catalogmcp` exposes shared read-only Control tools over stdio and optional stateless HTTP. Stdio uses `internal/platform/controlclient` for origin-bound API requests, explicit credentials and bounded responses. The API's `/mcp` route uses an in-process reader with the same authorization rules. Neither transport follows resource references or executes resources. See the [MCP guide](../guides/mcp-server.mdx) for setup and limits.

### Implement ports against real systems

`internal/platform/database`, `fetcher`, `embeddings`, `trustevidence`, and `webhooksender` implement domain-facing contracts with PostgreSQL or controlled external systems. `trustevidence` acquires public ANS evidence through the hardened fetcher; the offline verifier under `internal/standards/anstrust` checks its exact bytes. Provider details do not leak inward.

**Format packages and source assets have narrower roles.** `internal/adapter`, `internal/standards`, `internal/jsondoc`, `internal/draftfile` and generated `internal/a2apb` interpret exact formats without owning lifecycle policy. OpenAPI defines the implemented HTTP contract, including the reusable draft-file schema. Numbered migrations define forward-only database changes. Vendored schemas pin supported formats, and configuration profiles provide strict startup examples. There is no competing generated copy of these authorities.

Dependencies point toward service-owned contracts. Domain packages own lifecycle rules and ports. Format packages interpret pinned representations. Platform adapters implement ports without passing HTTP, SQL, Kubernetes, cloud or provider SDK types into domain code.

## Implementation style

### Explicit construction

Services receive options and narrow ports through constructors. `runtime.Build` is the visible composition root; hidden globals and package initialization do not choose production dependencies.

### Plain Go boundaries

The pinned Go toolchain uses standard [`net/http`](https://pkg.go.dev/net/http) routing and [`context.Context`](https://pkg.go.dev/context). Typed domain errors, explicit `pgx` repositories and small packages keep control flow visible without a service framework.

### Interfaces on demand

A port belongs beside the domain behavior that needs it and appears only when a real caller and implementation exist. The repository avoids speculative provider layers, empty target packages, and dormant abstractions.

### Dependencies for deterministic tests

Clocks, UUID generation, fetchers, senders, and domain-owned stores can be injected for tests. Cancellation and deadlines apply across blocking boundaries. Tests of provider behavior use the real dependency in a disposable environment.

## Where a change belongs

| If the behavior changes... | Start with this package | Follow the change through |
| --- | --- | --- |
| A Catalog lifecycle, invariant, search rule, identity decision, publication rule, source rule, Job state, audit record, public event, or webhook policy. | The applicable package under `internal/catalog`, `identity`, `publication`, `federation`, `jobs`, `audit`, `events`, or `webhook`. | Update canonical types, service behavior, narrow ports, safe errors, and focused positive and negative tests before adapting HTTP or SQL. |
| An implemented API-listener HTTP route, field, default, authorization rule, status, header, or error. | `api/openapi/control-v1.yaml` and `internal/platform/httpserver`. | Keep route registration, strict request/response types, authorization, OpenAPI, examples, API conventions, and contract tests in one change. |
| Persistent state, a constraint, RLS policy, role privilege, query, transaction, lease, or migration. | The owning domain port plus `internal/platform/database` and the next numbered migration. | Preserve compatibility with supported releases, not obsolete development formats, and prove migration, repository, RLS denial, role, concurrency, and repair or rollback behavior against disposable PostgreSQL 18. |
| An Agent, MCP Server, Skill, Plugin, ARD, AI Catalog, JSON Schema, or JSON-LD rule. | `internal/adapter` or `internal/standards`, with the applicable pinned profile under `schemas`. | Preserve raw evidence, update compatibility fixtures and profile notes, verify checksums, and run the focused conformance or fuzz boundary. Never edit a vendored profile in place. |
| A source, external representation, redirect, credential route, webhook destination, OTLP export, or other outbound HTTP behavior. | The owning domain plus the shared `internal/platform/fetcher` boundary. | Keep exact origin and network policy centralized; add DNS, IP, redirect, timeout, byte, cancellation, and disclosure tests rather than constructing a feature-local `http.Client`. |
| Durable asynchronous work. | The owning domain and `internal/jobs`; wire the concrete handler in `internal/platform/runtime`. | Define a bounded payload and result, then prove lease ownership, heartbeat, cancellation, retry class, terminal evidence, process interruption, and idempotent side effects. |
| A runtime setting or feature gate. | `internal/platform/config`. | Update strict parsing and validation, every affected JSON profile, the explicit environment allowlist, safe diagnostics, configuration reference, and Compose or Helm wiring where applicable. |
| The binary, image, Compose topology, Helm chart, probe, security context, or release input. | `cmd`, `Containerfile`, `compose*.yaml`, or `deployments` as applicable. | Keep compatibility copies synchronized and add the container, functional, Helm, deployment, startup, shutdown, or upgrade evidence required by the changed boundary. |

## A command through the code

A production mutation passes through HTTP authorization and its owning domain service. A domain-owned repository port provides PostgreSQL access. The command first reserves its idempotency key in a short transaction. External preparation then finishes before the protocol-v2 domain write transaction. That transaction commits the domain result, classified audit/outbox evidence and retained response together.

## Background work path

Workers recover through durable leases. No correctness depends on one process surviving. For Jobs that commit domain changes, that commit precedes the later lease-owned Job outcome. These handlers must remain safe to retry after interruption between the two writes.

1. **Jobs table** Queued, scheduled, deduplicated work

1. **Claim lease** `FOR UPDATE SKIP LOCKED`

1. **Bounded handler** Heartbeat, cancellation, safe fetch, staged evidence

1. **Commit domain result** Owning transaction with audit/outbox where applicable; retry-safe side effect

1. **Record Job outcome** Verify lease owner; succeeded, waiting, failed, cancelled, or dead letter

ANS registration assessments stage their bounded private result and required audit record without a separate domain commit. PostgreSQL completion checks the current source and live lease, then commits the private result, succeeded Job state and required audit together. Cancellation, an expired lease or an audit failure prevents completion. A succeeded assessment Job can contain a negative or insufficient verification result. See [assessment operations](../operations/federation.mdx#request-an-ans-registration-assessment) for selection, disclosure and current applicability.

## Boundary verification

`make architecture-check` enforces the import and outbound-client construction rules that can be checked from source. Domain tests exercise owning rules through narrow ports; `internal/integration` composes those services with in-memory dependencies. Fake transactions and loopback fixtures support focused failure tests, but do not prove PostgreSQL SQL, RLS, locking or deployment behavior.

Real database guarantees use `make test-integration`; process, persistence and transport interactions use the owned Compose and Helm scenarios. The [testing strategy](../contributing/testing.md#test-boundaries) explains target selection and coverage accounting. Follow the [contributor workflow](../../../../../CONTRIBUTING.md) for change-specific verification and documentation requirements.

## Why a modular monolith fits

Lifecycle, publication, audit, idempotency, and outbox transitions need one visible transaction model. Separate API and worker processes provide independent scaling without turning every domain boundary into a distributed consistency problem.

See [design principles](design.mdx) for the durable evidence, transaction and federation invariants, and [local development](../guides/local-development.mdx) to run the service and exercise its API.
