Optional webhooks use signed HTTPS notifications with at-least-once delivery. Durable dispatch deferral, stopped-runtime owner-only ciphertext maintenance, bounded event admission, recipient-aware retention and loss reconciliation preserve exact runtime authority. Signing-key rotation and emergency revocation are separate from deployment encryption-key replacement. See [Webhook operations](webhooks.mdx) for compromise handling and historical backup keys. Production receiver and recovery qualification remains specific to the selected deployment.

Use this runbook to verify the minimum security controls for a deployed Catalog service. It complements the [threat model](../architecture/security.mdx#threats-and-principal-controls). Qualify the selected production deployment separately from the tested development baseline.

Only two fixed owner-authorized trigger functions can update them.

Housekeeping does not delete audit evidence. Export-file self-consistency does not prove backup provenance or detect a database owner rewriting both the database and export. Recovery-point comparison requires a separately trusted manifest captured with the database during one quiesced-writer interval.
- Treat HTTP read and write timeouts as socket protections, not as the product-handler deadline. ADR-0014's `http.requestTimeout` provides one cooperative deadline through authentication, decoding, idempotency coordination, database and outbound calls, bounded domain work, and response encoding for authenticated Control API and host-bound public-discovery routes. Operational and static routes remain outside it. Publication, safety-withdrawal, referral, live, conflict, topology, and current-observation work is independently database and memory bounded because a timeout cannot repair an unbounded algorithm.

  PostgreSQL's native cancel request keeps an acknowledged canceled session usable, while a fixed 500-millisecond network fallback closes an unresponsive connection rather than risking reuse. This is an internal driver policy, not a tenant setting. Fixed cancellation-independent PostgreSQL cleanup stays outside the product-work deadline but shares one five-second absolute bound and may only roll back, complete already-produced atomic command state and its exact replay response, persist a failure response after rollback, release the advisory lock, or discard the connection. It performs no new business work.

  Do not use a detached timeout handler, per-route or tenant timeout policy, or PostgreSQL `statement_timeout` as the request contract. Cross-validate socket, shutdown, ingress, and Kubernetes termination bounds with that finite work-plus-cleanup envelope. Focused tests prove fixed equal-priority Job and automatic-source work advances across tenants without a tenant scheduler. Each process permits only one publication construction at a time. This limits memory use for the only synchronous operation currently shown to require substantial memory.

  Add another process-local or database-authoritative admission control only when reproducible contention evidence requires it. Ingress remains responsible for general client-rate policy but is not the process memory-safety boundary. The implemented low-cardinality deadline and admission signals, redacted correlation logs, bounded diagnostics, and worker-only operations surface remain platform-network inputs. They do not replace those execution controls, ingress isolation, or SRE-selected monitoring.

The OIDC verifier supports an optional issuer-specific private CA. Independent-provider tests use a digest-pinned Keycloak container for discovery, JWKS and access-token compatibility. Controlled tests cover malformed responses, rotation, caching and outages. Under [ADR-0003](../architecture/decisions/0003-runtime-packaging-and-local-test-environments.md), Keycloak is an external test tool, not a Catalog dependency or distributed artifact.

Its official image contains components under several licenses and has [known vulnerabilities](../contributing/testing.md#functional-coverage-inventory). These tests do not qualify a deployment's actual issuer. Deferred security and governance capabilities remain unavailable or explicitly `not_assessed`.

## Key and secret handling

- Generate cursor-signing and database credentials independently, along with source credentials and webhook encryption/signing secrets only when those capabilities are used. Do not reuse key material across purposes or environments.
- Deliver runtime secrets through the SRE-selected injection mechanism. Resolve source credentials only through opaque governed bindings when that capability is enabled. Diagnostics use an explicit safe-field report with secret presence counts and do not serialize DSNs, development bearer values, or cryptographic keys.
- When webhooks are enabled, rotate endpoint secrets through the versioned rotation API. Treat the returned secret as one-time material and verify delivery before retiring the previous receiver configuration.
- A compromised webhook encryption or signing key requires impact analysis, rotation, affected-delivery review, and receiver notification when that capability is enabled. A compromised cursor key invalidates outstanding cursors and requires coordinated rotation.
- Preserve historical verification material. The current service has no configured governed-evidence retention period or automatic destruction path. Governed retention, legal hold and privacy-erasure automation are not implemented. Do not treat operational housekeeping as permission to delete governed history.

## Credential and authorization limits

The Catalog API validates signed bearer JWTs and current Catalog membership. This resource server does not issue tokens, perform delegated token exchange, introspect tokens on each request, or revoke a delegated credential chain. The optional UI host and human CLI exchange authorization codes with the configured issuer during login. Expiry and signing-key rotation affect token verification. Membership suspension/offboarding and role revocation affect current Catalog access even while a token remains unexpired. Publication withdrawal affects discovery, not the external resource's credentials or runtime. Follow the [membership procedures](../guides/access-management.mdx#suspend-or-offboard-a-membership), [password-login tutorial](oidc-keycloak.md#run-the-interactive-local-tutorial) and [maintenance runbook](maintenance.mdx) for their separate operations.

[DPoP](https://www.rfc-editor.org/rfc/rfc9449.html#section-7) and [certificate-bound tokens](https://www.rfc-editor.org/rfc/rfc8705.html#section-3) require receiving-side proof checks beyond a JWT signature. Catalog does not enforce those checks or interpret a delegated [`act` chain](https://www.rfc-editor.org/rfc/rfc8693.html#section-4.1). A `cnf` claim or proxy header does not establish proof of possession. If deployment policy requires a gateway to enforce proofs, establish that enforcement and prevent direct backend bypass; Catalog configuration alone supplies no such guarantee. OIDC HTTPS private trust and mounted outbound client certificates serve different connections and do not provide these inbound controls.

Keep caller credentials, approved source credentials and target-side invocation credentials separate. Do not store live claims, private keys or bearer tokens in resource metadata or forward a caller's Catalog token to a discovered endpoint. Renewal and injection belong to the deployment's credential mechanism. See [identity and client handoff](../guides/integrating.mdx#keep-identities-and-credentials-separate) for the two flows and [authentication configuration](../reference/configuration.mdx#authentication-and-catalog-identity) for exact accepted claims.

## Federation and public-surface controls

- Treat every source URL, redirect, DNS response, media type, body, nested catalog, embedded value, and Registry result as untrusted.
- Apply the same Trust Manifest types and declared publisher alignment to complete entries and sparse live results. Omit invalid live entries without hiding healthy results. Retain invalid indexed entries as private evidence without a search projection. These checks do not verify signatures or fetch evidence URLs. [Standards tests](../../../../../internal/standards/ard_trust_test.go), [ingestion tests](../../../../../internal/federation/observation_test.go), [live admission tests](../../../../../internal/federation/live_result_test.go) and [HTTP tests](../../../../../internal/platform/httpserver/ard_live_validation_functional_test.go) cover this boundary.
- Disclose valid live peer Trust Manifests only through existing source, tenant, host and audience controls. Preserve raw Control evidence and keep peer claims separate from local publication. Do not combine duplicate claims or treat a declaration as verified trust. [Projection units](../../../../../internal/platform/httpserver/public_live_projection_test.go) and the HTTP tests cover these rules.
- Source inspection requires tenant `source.inspect`; source registration requires tenant `source.manage`. Both commands also require `sources.manage` when OAuth scopes are enforced. Built-in roles supply these Catalog permissions, and administrators can delegate them through custom roles. Deployment administrators still control topology and outbound network policy. External catalogs do not self-register.
- Treat the administrator's active source revisions as the federation authority. Ordinary Search callers cannot submit a Registry URL, choose an unapproved source, broaden its resource scope, or change its discovery audience. ARD request modes operate only within the approved source set.
- Load the reviewed deployment federation policy on every API and worker. Production uses an explicit public-origin allowlist by default; `any_public_https` requires a deliberate operator choice, and every private destination requires an assigned named profile with an exact origin and bounded address range.
- Route external representations through that same public policy without a caller-selected network profile or credential. A policy digest change makes prior URL evidence non-current. - Live search contacts only Registries in the administrator-approved topology. Cap response bytes, redirect count, nesting depth, fanout, approved referral depth, deadlines, page sizes, filters, and cursor lifetime. Track a request-local visited set. Do not delegate unbounded upstream `auto`. Alert on repeated limit violations or partial federation.
- Require an administrator acknowledgement before a source can receive live query text or supported filters. Do not send caller identity, tenant identifiers, roles, groups, local visibility, internal policy, or unrelated context, and do not prompt ordinary users for topology decisions on each search.
- Do not expose raw source bodies, internal diagnostics, source credentials, draft records, unpublished releases, or tenant identifiers through public ARD and AI Catalog responses.
- Publication activation must fail when eligible membership changes after candidate construction or when referenced artifacts are unavailable.

- Exact discovery-host mappings and modes. Active anonymous or authenticated snapshot membership, exclusions, artifact allowlist, profile versions, cache isolation, withdrawal behavior, and rollback readiness.

## Incident actions

For suspected compromise, stop the unsafe path before preserving availability: pause the affected source, disable the affected webhook endpoint, revoke the affected release, unpublish its configured host, rotate exposed credentials, or isolate the tenant as appropriate. Publication snapshots remain immutable evidence and are deactivated rather than deleted. Preserve request IDs, immutable revisions, audit events, source observations, delivery attempts, object digests, and deployment evidence without copying secrets into the incident record.

Follow [incident response](incident-response.md) for triage, containment, recovery, and verification. Follow [backup and restore](backup-restore.mdx) when recovering PostgreSQL-backed Catalog state. Do not restore a snapshot into service until tenant isolation, key state, migrations, public publication state, and webhook delivery safety have been revalidated.

## Private item feedback

Only active humans with current `feedback.own` submit. Item-context reads independently require `resource.read`. Own records are membership-bound and another tenant or Reader cannot retrieve them by ID. Current `feedback.moderate` grants permit triage, not rewriting another submitter's comment.

The `feedback.write` scope does not grant authoring rights. Feedback request objects accept only documented fields. Comments and responses are plain text. Current authorization, record-specific ETags and text-free durable replay prevent stale updates or replay-based recovery of removed text. The feedback service/HTTP tests cover these controls, and PostgreSQL integration tests cover RLS, exact grants and competing writers. Browser and packaged journeys cover the actual reader/admin workflows.

## Local demo archive boundary

The opt-in development-only [demo archive route](../reference/configuration.mdx#development-demo-archives) admits only one literal local HTTPS origin and a prepared allowlist of exact Plugin archive paths, digests and sizes for the fixed development tenant (at most 64 ZIPs, each at most 64 KiB). Strict environment/authentication admission, exact paths/digests, private trust, pinned single-IP dialing and anonymous redirect-free requests keep this exception separate from ordinary public representation fetching and federation credentials. `internal/platform/config/demo_archives_test.go`, `internal/platform/runtime/demo_archives_test.go` and the real-TLS `demo_archives_functional_test.go` cover startup/preflight denial, disabled routing, exact archive reads, tamper, oversized responses, untrusted TLS, redirects and outages. The fixture's private key is ignored local state. No key, token or archive runtime is shipped or executed.

## External image display

Listing images use exact operator origin bindings and the existing hardened outbound boundary. The service refuses redirects, credential-bearing URLs, unsupported image formats, malformed images and byte or pixel overflows. Private routes retain tenant assignment, CIDR and TLS checks. Image requests inherit no source credentials, cookies or client certificates.

Sealed descriptors bind exact image bytes; native icons validate current bytes as mutable display hints. Live image reads require a short-lived signed result receipt plus current discovery authority. Receipts bind the tenant, principal, source generation and revision, authorization, policy, credentials and override state. A receipt is not an authorization grant.

Image bytes are transient. Responses use a canonical content type, `Content-Digest`, `nosniff` and `no-store`. Browser object URLs are bounded and revoked when their owner changes. The UI image CSP permits `blob:` without adding external image hosts. Rights assessments remain `not_assessed`; they are not a legal verification service.

## ANS verification authorities

The optional [ANS configuration](../reference/configuration.mdx#ans-registration-verification) loads accepted public keys and authority rules at startup. It supports an offline verifier and explicit [source assessments](federation.mdx#request-an-ans-registration-assessment). Durable Jobs retain bounded evidence and complete with their audit record in one transaction. Ordinary discovery does not fetch registration evidence or require ANS availability. Indexed assessment requires exact retained evidence in the source's current complete snapshot, including its current revision. An unchanged observation can qualify after synchronization without changing its original evidence.

Select a policy on the approved source before requesting an assessment. Each request selects exact entry bytes, source revision and native variant. Workers check the source, loaded policy, credentials, lease and cancellation before each evidence request and before completion. Generic Job responses omit private evidence.

The UI separates policy editing from assessment requests. Requests need current source management, source-evidence and federation-discovery permissions plus the applicable OAuth ceiling. Indexed selection reads raw evidence only after an explicit action. Live selection retains the server's digest and original query text; the browser never derives authority from reserialized JSON. Result reads require current Job and source-evidence permissions and an audit write before disclosure.

The browser's dedicated assessment route uses `sources.read`, not the generic Jobs route's `catalog.read` scope. It reads no evidence on page load. It checks consumed fields, source binding, canonical base64 and the original entry digest before display or download. A failed refresh clears previous evidence. Identity changes and sign-out discard results and revoke temporary download links.

Evidence downloads reuse the audited read without contacting external URLs. The [HTTP tests](../../../../../internal/platform/httpserver/trust_functional_test.go) check these access and replay boundaries.

Signed JSON field names are case-sensitive. Unknown signed extensions cannot replace required claims. The [signed-field tests](../../../../../internal/standards/anstrust/event_fields_test.go) check this rule with valid signatures and malformed claim names.

Obtain registration-authority and log public keys through a separately trusted operator channel. Confirm their complete SHA-256 SPKI fingerprints before deployment. Do not use receipt contents, embedded keys, key hints or `/root-keys` as authority. Publisher-domain permission accepts that authority's statements; it does not prove publisher ownership. Keep verification public keys separate from TLS CA bundles and private credentials. Restrict write access to their files or ConfigMaps.

Prepare one named policy with the exact authority names, publisher domains and evidence origin. Add that origin to the existing federation policy. For private ANS services, supply an existing tenant-assigned network profile, approved address ranges and TLS CA bundle. This profile uses public, credential-free evidence endpoints. Authenticated endpoints are unsupported. No source token, cookie, client certificate or ambient proxy credential is forwarded.

Deliver identical settings and public keys to API and worker. For Compose, select a public-key directory with `CATALOG_COMPOSE_TRUST_VERIFICATION_DIRECTORY`. For Helm, create a ConfigMap from your public PEM files and set `trustVerification.publicKeysConfigMap`. Use `/etc/open-agentic-catalog/trust-verification/<file>` in each policy. Mounting keys alone does not activate verification. Set `enabled: true` and restart both roles to load the policy.

No startup request contacts ANS. The [local peer regressions](../contributing/testing.md#enabled-verification-with-other-local-peers) check that enabled verification leaves ordinary discovery independent of ANS. Missing native evidence remains incomplete; it does not grant trust.

For rotation, add an independently accepted replacement key before the producer uses it. Log keys can overlap when their complete fingerprints and lookup hints are distinct. Registration keys can overlap only with distinct producer key IDs. A producer that reuses its registration key ID requires a coordinated key cutover. Do not duplicate a key ID or fetch a replacement automatically.

Restart both roles after key changes. Remove retired keys through another controlled rollout.

Keep an old log key while evidence still needs its signatures. A new receipt does not replace an older sealed event's signature. Removing the old key can prevent a fresh assessment of that event, even when current TL endpoints use the new signer. Key removal does not delete earlier evidence or revoke the upstream registration. The [local ANS qualification](../../../../../test/interoperability/ans/README.md#real-local-assessment-qualification) tests actual RA/TL changes, accepted-key overlap, removal and restoration.

Changing a referenced ConfigMap's contents does not automatically restart Helm workloads. Use a new ConfigMap name or explicitly roll both roles. API and worker can temporarily hold different settings during a rolling update. There is no hot reload or atomic cluster-wide activation guarantee. Policy digests identify loaded authority and routing settings without exposing them.

To disable the prepared capability, set `enabled: false` and restart both roles. Disabled processes do not read verification keys and require no ANS service. Disabled APIs reject new requests. Existing work requires worker rollout or supported cancellation; an in-flight request cannot be recalled. Disabling preserves authorized historical evidence without presenting it as currently verified. Registration verification never changes broad trust, rights, publication eligibility or execution permission.

## VS Code package consumption

Complete Skill installation in the optional VS Code client requires a trusted writable filesystem workspace on Linux, Windows or macOS, current release access and an exact retained package inventory. Native package installation is qualified on Linux amd64; Windows/macOS implementation has no native execution qualification. Git/OCI tools receive no Catalog credentials. Archive and path checks reject links, collisions and unsafe files. Staging stays outside native discovery; changed local files stop replacement or removal. Installation does not execute package scripts.

The [client guide](../../../../../extensions/vscode/README.md#install-a-complete-skill) documents limits and recovery; the [extension harness](../../../../../test/vscode/README.md#complete-skill-package-qualification) owns the isolated and real-host controls.

Agent Plugin installation in the optional VS Code client requires current local release access and complete inspected archive evidence. Anonymous HTTPS acquisition has separate package trust, fixed byte limits and exact file verification. The extension installs outside automatic discovery and registers the owned absolute path as disabled. Whole-package activation needs a separate component preview and fresh consent. Native organizational policy, trust and process controls still apply. Unsupported matcher/placeholder semantics prevent activation. Local edits block replacement and deletion; disabling works offline. The [client guide](../../../../../extensions/vscode/README.md#install-and-activate-an-agent-plugin) explains machine-wide scope and recovery. [Isolated, HTTPS and actual-editor checks](../../../../../test/vscode/README.md#agent-plugin-qualification) cover these boundaries without public services or models.

Local removal binds the confirmed receipt, ownership binding and full inventory under the installation lock before changing files or Plugin settings. Healthy tools remain independently manageable beside a damaged receipt. Recovery can disable exact validated pending private registrations without adopting or deleting an unowned tree. Reveal rechecks a contained unchanged tree; inventory comparison performs no acquisition or activation. The [inspection/local-tool test map](../../../../../test/vscode/README.md#inspection-references-and-local-tools) identifies filesystem and actual-editor controls, including replacement while consent is held and preservation of damaged receipts and unrelated keys.

Live and Published-auto consumer revalidation requires new peer-query consent for each frozen-page replay, including MCP startup and Agent send/read/cancel. Current session and consumer guards run again after consent and before HTTP; an initial selection change, declined consent or cancellation must send no replay or target request. Native MCP preparation combines its cancellation signals through verification, document reads and prompts. The actual progress-button/TLS-closure check is separate from injected credential tests and does not claim that VS Code 1.141.0 supplies a cancellable provider token.

Private package credentials are separate SecretStorage entries, bound to the execution host, Catalog account, source family and exact HTTPS origin. Native selection is explicit for each acquisition. Git's temporary origin-header file is deleted on success, refusal and cancellation. Private OCI permits Basic or one bounded same-origin registry token exchange with the selected repository's pull scope; cross-origin token realms and redirects are refused. HTTPS archives accept explicit Basic/Bearer only on their bound origin. No ambient Git/Docker or Catalog credentials are imported. Offline forgetting preserves the other credential families. See the [package guide](../../../../../extensions/vscode/README.md#private-package-credentials) and [owned TLS regression controls](../../../../../test/vscode/README.md#additional-client-capabilities-and-linux-qualification).

Personal ratings and feedback use the existing API's current permission, OAuth scope, tenant, ownership, ETag and idempotency checks. Native private input and exact uncertain-command recovery remain in memory; own-list reads and withdrawal do not inspect a now-inaccessible resource. Recovery never silently creates a new key and expires locally after ten minutes. Inert saved MCP references retain only exact identifiers, positions and digests; reselection requires fresh access, evidence and consent. Windows/macOS policy branches are implemented without native execution qualification.

## VS Code A2A conversations

A2A conversations are explicit client actions, not Catalog execution. The extension rechecks current access and the unchanged Card before each send, read or cancellation. Destination/prompt consent, workspace trust, separate target credentials, strict TLS and fixed response/stream limits protect direct agent traffic. No Catalog token, cookie, editor content or local history is forwarded automatically. Unknown send outcomes are never retried. Disconnect does not prove remote cancellation.

Transcripts remain in memory unless explicitly exported. The [consumer guide](../../../../../extensions/vscode/README.md#talk-to-an-agent) lists supported authentication and unsupported protocol features; the [local qualification](../../../../../test/vscode/README.md#a2a-conversation-qualification) checks these boundaries.
