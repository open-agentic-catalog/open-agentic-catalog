# Catalog client and operator commands

This command combines explicit remote API reads with focused local operator workflows. Select the command's documented authority and target before running it: migration, repair, provisioning, smoke and seeding can change state.

| Files | Responsibility |
| --- | --- |
| [main.go](main.go) | Command dispatch, configuration/profile reports, diagnostics, migration and focused operator workflows. |
| [remote.go](remote.go), [remote_transport.go](remote_transport.go) | Remote reads and explicit reindex commands, flags, bounded response envelopes, fixed-origin transport and safe diagnostics. |
| [export.go](export.go), [export_record.go](export_record.go), [export_draft.go](export_draft.go), [export_mcp.go](export_mcp.go), [export_transport.go](export_transport.go), [export_files.go](export_files.go) | Exact release/revision selection, native, reusable draft or remote MCP client configuration downloads, lossless native text and private files with explicit digest scopes. |
| [import.go](import.go), [import_prepare.go](import_prepare.go), [import_apply.go](import_apply.go) | Offline native preparation and authorized draft apply/resume with private recovery receipts. |
| [probe.go](probe.go) | Literal loopback health probes with fixed paths, short deadlines and bounded response bodies. |
| [webhook_secrets.go](webhook_secrets.go) | Webhook encryption-key maintenance commands and operator inputs. |
| [smoke.go](smoke.go) | Disposable API lifecycle and discovery exercises with shared request/payload helpers. |
| [seed_demo.go](seed_demo.go) | YAML-driven curated samples, explicit legacy fixture selections, bounded API loading and verified local receipts. |

Remote commands receive their own API origin, token and trust inputs; they do not compose the runtime or use SQL. Database operator actions remain in the [database package](../../internal/platform/database/README.md). Command entry points supply authority and output handling without implementing domain transitions themselves.

Online import and export accept `--login-file` through the same human credential provider as `remote`. Use `--issuer-ca-file` for private issuer roots during refresh. Login files exclude explicit and inherited bearer credentials. Offline import preview needs no credentials. [Credential-selection units](draft_auth_test.go) check parsing and conflicts without network calls; the packaged OIDC journey checks actual import/export and issuer refresh.

`catalogctl export --release-id UUID --output-dir PATH` saves one selected native document or external package references. Add `--representation-id UUID` when several representations exist. Existing paths and symlink ancestors are refused. `export.json` is the final completion marker. Exact retained bytes and inline JSON have distinct digest scopes; external Skill/Plugin archives are never fetched or reconstructed. See the [export reference](../../documentation/src/content/docs/reference/commands.md#export-a-native-document) for limits and file semantics.

Add `--format draft` to save every representation and the release's exact Listing metadata in `draft.json`. Alternatively, select `--version-revision-id UUID` and optional `--listing-revision-id UUID`. Exact reads require current metadata and content permission, without history permission. Readable incomplete drafts can export. Draft mode rejects representation selectors, including selection-file entries. `export batch --format draft` keeps the existing frozen selection, byte budgets and per-item outcomes. The result reports browser text-size compatibility separately from native validity or readiness to save. See [reusable draft downloads](../../documentation/src/content/docs/reference/commands.md#export-a-reusable-draft-json-file) for examples and package requirements.

Use `--format mcp-vscode`, `mcp-claude-code` or `mcp-cursor` for one remote MCP connection. Select `--remote N` when several remotes exist. The command writes private client JSON and setup notes, without header values or client-settings changes. See the [client configuration reference](../../documentation/src/content/docs/reference/commands.md#export-an-mcp-client-configuration) for supported profiles, transports, output files and authentication setup.

[Shared fixtures](testdata/mcp-client-export/cases.json) define the CLI/browser projection contract. Isolated [units](export_mcp_test.go) cover parsing, selection, omission and files. The [functional suite](export_mcp_functional_test.go) runs the real command against owned TLS fixtures; the existing governed export journey also checks all three client formats.

The [access and audit tests](export_mcp_access_functional_test.go) exercise real Catalog permission checks and HTTP responses with a fixed native-acquisition double. They verify scoped metadata access, content grants and revocation, superseded/deprecated releases and attributed artifact-read audits.

[Draft export units](export_draft_test.go) check selectors, exact metadata bindings, response fidelity, limits and safe output. [Draft export functional tests](export_draft_functional_test.go) run the compiled CLI against an owned local Catalog. They cover all four kinds, blocked multi-representation drafts, package-only Skills, scoped access without history permission and revoked access.

[Reusable-file preparation](import_draft.go) adapts the shared file to the existing native validators. [Destination binding](import_draft_apply.go) selects finite create/Version/Listing plans. Both file types share command acknowledgements, exact readback, durable receipt writes and replay checks in [import_apply.go](import_apply.go). Native receipts keep their four-command items; reusable receipts contain only actual writes. No package paths or destination identities come from the reusable file.

[Isolated import tests](import_draft_test.go) use a controlled transport without listeners or application runtime. They cover all six plans, response loss at each command, blocked evidence and changed-intent refusal. [Compiled CLI tests](import_draft_functional_test.go) cover all four kinds, checksum refusal, scoped authoring and tenant isolation. The PostgreSQL process fixture adds cross-replica replay and exact SQL numeric assertions. See [reusable-file import](../../documentation/src/content/docs/reference/commands.md#import-a-reusable-draft-json-file) for flags, permissions and recovery.

[Export units](export_test.go) and [artifact transport units](export_transport_test.go) cover consumed identities, raw numbers, delivery distinctions, integrity disagreement, bounds, private files, collisions and cleanup. [Export functional tests](export_functional_test.go) exercise the compiled command against all four governed kinds, current scoped content permissions, cross-tenant refusals, private TLS, redirects, truncated responses and a real socket deadline. The ordinary unit/local functional targets discover these tests; no dedicated environment or Make target is required.

The [portable discovery Skill](../../examples/client-skills/catalog-discovery/README.md) uses these remote commands. `make client-skill-check` runs colocated package/CLI contract tests, including release retirement and current permission admission. The session-handler tests run by default; only `TestClientSkillSessionFixture`, the time-bounded loopback session for manual assistant qualification, is opt-in. See [Skill verification](../../documentation/src/content/docs/contributing/testing.md#assistant-discovery-skill).

[Remote transport units](remote_transport_test.go) and [probe units](probe_test.go) use controlled responses to verify request binding, response bounds, error classification and cleanup. The entry points retain origin/loopback validation and client construction; real TLS, redirects and socket deadlines remain functional tests.

[Smoke-helper units](smoke_test.go) cover inert client policy, bounded responses, conditional headers, response-header ownership and check-history updates. [Capabilities units](smoke_capabilities_test.go) validate static response bytes for governance, limits and the required resource-kind/operation subset, preserving extra capabilities, ordering independence and the existing search-state validator. The complete smoke walkthrough and report remain owned by [functional smoke tests](smoke_functional_test.go). Those tests also intercept real namespace responses to remove the create ID or ETag, change the update revision or ETag, or return a redirect to an owned listener. Each fault must stop the workflow at the intended check with an empty report, no later workflow request and no redirect follow, while preserving the successful namespace mutation already committed by the service.

Additional smoke functional cases validate the real successful response before removing the required request metric, domain approval, Search generation, expected ARD member or publisher facet, or replacing a public document's digest. Each case preserves HTTP success and checks the exact workflow failure, an empty success report and no later requests. Completed publisher approvals and active snapshots remain stored; smoke rejection does not roll back earlier commands. Existing helper units and the successful complete walkthrough retain their separate assertions.

[Local unit tests](local_unit_test.go) validate operator plans without database connections. [Publication-client unit tests](smoke_publication_unit_test.go) inject static HTTP responses to verify rejection, command/actor/revision bindings and stopping after failure without starting a Catalog or listener. [Administration-client unit tests](smoke_administration_unit_test.go) use the same transport for membership pagination/lifecycle evidence, draft deletion, hidden descendants and reserved identifier checks. [Demo-item unit tests](seed_demo_unit_test.go) verify creation stopping points, partial receipts and retained-evidence comparisons for the five built-in fixtures. [Demo-verification unit tests](seed_demo_verification_unit_test.go) check exact inventory sets, parent/snapshot evidence, public manifest membership and local search identities with static responses. [Demo-creation unit tests](seed_demo_creation_unit_test.go) protect completed-item receipts, failure attribution and publication preconditions across the fixed dataset.

[Configured sample units](seed_demo_configured_unit_test.go) and [expanded sample units](seed_demo_expanded_unit_test.go) check receipt identity, publisher binding, report counts and snapshot membership, including package-only Skill exclusions. [Intent units](seed_demo_progress_unit_test.go) bind collections to their parents and distinguish matching fixtures from unrelated records. Static inventory responses check exact cursor encoding, the cursor byte boundary, duplicate identities and refusal without partial results or further requests. [Remote argument units](remote_test.go) preserve exact filters, record byte budgets, timeouts and reindex inputs. Complete loading, journal recovery and real HTTP behavior remain functional.

[Webhook-maintenance units](webhook_secrets_test.go) cover bounded key decoding, mounted-file replacement and preflight failures before config/database access. Maintenance keys must be regular files of at most 1024 bytes; symlinks to regular mounted secrets work, and FIFO inputs are rejected without waiting for a writer.

Run `go test ./cmd/catalogctl -shuffle=on -count=1` for isolated CLI validation and controlled-transport tests. Add `-tags=functional` for real probe, remote, smoke, demo and composed Skill workflows. The manual session additionally requires its explicit activation variable. See the [command reference](../../documentation/src/content/docs/reference/commands.md) for supported syntax and linked runbooks, and [local development](../../documentation/src/content/docs/guides/local-development.mdx) for disposable smoke and demo targets.

Terminal errors project reviewed operation/code guidance to stderr without printing dependency chains, private paths or supplied flag values. Help omits environment-derived defaults. The remote client preserves its separately bounded JSON diagnostics and one fixed help response for both top-level and per-action help; command result JSON remains on stdout. OIDC trust-file guidance and strict configuration messages are deliberately retained. See [diagnostic boundaries](../../internal/platform/diagnostics/README.md).

Remote Search supports exact `--license`, repeatable `--category` and `--origin`, and local-only `--namespace`. Inputs use existing Control limits; the server normalizes categories and binds all filters to continuation. See the [remote command guide](../../documentation/src/content/docs/reference/commands.md#remote-catalog-reads).
