# Catalog process lifecycle

[main.go](main.go) parses the API, worker, combined development and version commands. It composes the selected [runtime](../../internal/platform/runtime/README.md), starts its listeners and background loops, and handles process signals. Combined `all` mode requires the in-memory configuration; production API and worker roles use separate PostgreSQL identities.

The supervisor retries explicitly classified dependency outages. Policy, configuration and invariant failures remain terminal, including joined errors containing a terminal cause beneath ordinary single-error wrappers. Explicit domain-error classifications retain their meaning. Each component uses the configured dependency restart windows (default 1s initial, 30s ceiling), independently doubles after short failed runs and samples the capped upper half.

A callback lasting at least 60s resets its current failure window; retry waits do not count. Cancellation is checked before callback admission. Healthy polling remains separate; see [worker dependency restarts](../../documentation/src/content/docs/reference/configuration.mdx#worker-dependency-restarts). Shutdown marks the process draining before stopping admission, then drains HTTP requests and background work within configured limits and closes shared resources.

[main_test.go](main_test.go) covers dispatch, help/version aliases, output-write failures and role help before configuration loading. Preflight refusals preserve reviewed guidance, stages and internal causes without implicit output. The same units check supervision classification and independent component-state updates through degradation and recovery.

[Retry classification tests](retry_classification_test.go) verify wrapped failure handling, terminal lease-conflict classification, caller cancellation and the default retry delay using virtual time. [Dependency retry tests](dependency_retry_test.go) prove window growth, saturation, reset, sampling, independent configured histories, terminal and fatal outcomes after a retry, caller deadlines during callbacks/backoff and exact timer admission.

[Supervisor observation units](supervisor_observation_test.go) check independent warning windows, sampled delays and private-cause exclusion. Filtering warnings preserves retry attempts and component-state updates. A held retry callback must report running before it returns; this does not establish readiness or successful dependency work.

[lifecycle_test.go](lifecycle_test.go) covers component completion accounting, retained drain errors and deadlines using controlled channels and virtual time. [Coordination tests](coordination_test.go) cover cancellation after the first-exit waiter blocks and operations-listener shutdown, including retained causes and the shared deadline. [Panic units](panic_test.go) check one completion per callback, safe error staging and fatal-marker retention when a sibling exhausts the shutdown budget. Run `go test ./cmd/catalogd -shuffle=on -count=1` from the repository root. Add `-tags=functional` for the embedded-trust subprocess and real listener tests in [main_functional_test.go](main_functional_test.go).

The combined memory role runs inside bounded test-binary subprocesses with either the API or operations address occupied. Each must return the intended bind failure without a drain error and release its sibling listener before child exit, while preserving the collision holder. These startup collisions do not prove every sibling reached readiness or replace the packaged drain journeys. The [command reference](../../documentation/src/content/docs/reference/commands.md#process-commands) owns supported flags; the [operations guide](../../documentation/src/content/docs/operations/overview.md) owns deployment procedures.

Terminal failures use reviewed stage/code/type projections on stderr. Every listener sanitizes standard HTTP fallback output. Owned component panics return a fatal marker, cancel sibling work and use the existing bounded drain; cancellation and retryable dependency errors cannot hide a panic. API request recovery remains transactional and distinct from process-fatal background faults. See [diagnostic safety and runtime limits](../../documentation/src/content/docs/operations/observability.mdx#current-safety-and-interpretation-limits).
