# Browser API boundary

`client.ts` owns the same-origin transport, session invalidation and fixed user-facing errors. Requests carry the UI host's required header and use cookies; the browser never receives the retained bearer. Consumers call `result` after response decoding so an earlier identity cannot repopulate the current workspace after a delayed body read.

`session.ts` checks runtime configuration and each host authentication reply before use. Runtime requires a canonical root/subpath, supported login mode and empty or credential-free HTTPS documentation URL. Session replies validate identity, finite permission arrays, policy revision, scope ceilings, bounded namespace grants and usable expiry. Valid expired replies become signed out.

Options must match the runtime mode and mounted alias/label constraints. Development login accepts only the configured Catalog path; OIDC accepts credential-free absolute HTTP(S) navigation with the exact authorization query preserved. The host remains responsible for issuer origin and environment policy.

Authentication methods have endpoint-specific result types. Session, options and login require JSON status 200. Logout requires bodyless 204. Invalid replies produce fixed errors with response-local correlation, never rejected values or parser text. Authentication transport and body failures are fenced against the current identity, including failures after headers arrive.

The exposed cancellation signal lets the shell guard later state changes too. Product `result(reply, check)` also rejects malformed consumed fields through explicit boolean predicates. It preserves the generated client's inferred result type without claiming that a partial check proves the entire schema.

Generating `schema.d.ts` does not validate responses at runtime. The existing client's used HTTP methods have a request-local wrapper around its documented fetch option: rejected body decoding becomes a fixed error retaining the actual response status, request ID and retry advice. Identity fencing applies to both successful and rejected decoding, including reference reads.

Decode each body once. Preserve raw `parseAs` modes.

For 429/503 failures, `retry-after.ts` accepts at most 128 characters of integer seconds or the three HTTP-date receive forms in UTC. The transport records one absolute time at header receipt, before body decoding. Only future advice within 24 hours is shown; malformed, elapsed or excessive hints are ignored. `APIError.retryAt` retains that time and its fixed safe message displays the local date/time. No timer, automatic resend or control lockout is created.

`acknowledge()` checks the documented 204 responses separately from JSON. Missing or malformed successful command data retains its actual success status and remains an uncertain outcome: no success message, automatic resend or replacement key.

`commands.ts` retains one idempotency key and prevents overlapping sends. A caller captures target, body and ETag before confirmation; the helper does not freeze or copy them. Keep an uncertain command available for an explicit retry with those same inputs.

`permission-keys.ts` owns the finite generated-contract-checked permission names. `session.ts` validates current tenant/any-scope/namespace permission hints, never role-name authority. `permissions.ts` supplies navigation and action hints; the any-scope union never authorizes an arbitrary namespace.

`access-responses.ts` in views validates fields consumed by bounded role, group, assignment and self-access screens. The backend still authenticates, authorizes and checks namespace scope on every request.

`reference.ts` projects read-only contract data using local JSON pointers without network reference resolution. Its area projection preserves declared tag order, appends exact undeclared names, and gives each operation one last-tag display home. Text, method and exact all-tag filtering remain independent of that grouping; only a literal true deprecation flag becomes a badge. Effective parameters retain their raw local references while resolved exact name/location keys establish path inheritance and operation overrides. Explicit malformed security overrides stay unavailable instead of inheriting an anonymous default. `localValue` follows at most sixteen local reference hops, rejects cycles and external targets, and preserves false, zero and null.

Revision evidence and validation replies carry the canonical Resource `namespaceId` in their response envelope. The UI uses it for exact permission hints without requiring a parent metadata read. It never sends that namespace in the closed validation request.

Custom-role requests accept only delegable actions from `GET /api/v1/access/permissions`. Its returned [permission descriptors](../../../api/openapi/control-v1.yaml) identify delegable actions and their required companion permissions. Protected `access.manage` remains unavailable. The backend enforces permission dependencies and the custom-role request bound.

Publication snapshot artifact IDs are lower-case, 64-character SHA-256 hex values, not UUIDs.

`workflows.test.ts` retains the typed API operation-to-workflow inventory and its assertions. The inventory detects unclassified API additions; it does not measure execution coverage.

The shared TypeScript configuration enables `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` in source, build and browser checks. Omit absent serialized request fields; allow explicit `undefined` only in local state or props that deliberately accept it. Guard indexed values, use fixed tuples where applicable, or document the local invariant behind a narrow assertion. The five typed unsafe-value lint rules reject unchecked assignments, arguments, calls, member access and returns. Narrow incoming `unknown` values where the client consumes them. A generated type or assertion cannot validate an external reply.

Regenerate `schema.d.ts` with the UI package's `npm run generate` after an authoritative OpenAPI change. `make ui-client-check` compares disposable generation with the checked-in declarations. Run `make ui-check` and the adjacent unit tests for transport, command, permission and contract changes. See the [test strategy](../../tests/README.md) for the complete gates.

## Consumed response inventory

Every product JSON result used by a screen has a consumed-field predicate in `views/responses.ts`, a dedicated decoder or the owning view. `checkAccess` owns current-access replies. `values.ts` supplies small object, scalar, array, page and cursor checks; it is not a JSON Schema interpreter. The checks cover consumed nested fields, state discriminators, usable timestamps, local link segments, finite counts and opaque continuation types. They do not normalize replies, reconstruct documents, hydrate detail records or impose smaller collection limits. Optional fields retain their API omission behavior.

`SourceArtwork.tsx` checks head, write and history replies against the exact source, presentation generation, identifier, kind and version presence/value. An omitted empty version string does not erase explicit version presence. A mismatched successful write reply retains the original command for deliberate same-key retry; it does not establish failure or trigger a refresh.

Keep these opaque values lossless: representation data/normalized facts/package/handoff evidence, document contents, listing extensions, Job results, full diagnostic objects and unknown evidence are rendered through escaped JSON or the existing bounded handoff/reference projections. Package evidence must be an object when present; its nested content remains opaque. Plugin file inventory is only counted/rendered; its array shape is checked without revalidating every file. Indexed diagnostic rows and live diagnostic entries are object-checked and rendered as JSON; counters and continuation controls used outside that renderer are checked separately. Source-test and webhook-reconciliation replies are object-checked diagnostic views, not decoded domain objects.

`ArtifactDownload` retains ArrayBuffer bytes and its digest verification. Version-document and observation-raw readers retain exact text. Reference replies remain unknown input to the tolerant read-only projector. These paths, together with the three documented bodyless command acknowledgements, are intentional exceptions to product JSON field predicates. Neither these checks nor TypeScript declarations establish complete OpenAPI/schema conformance; backend validation and functional contract testing retain that responsibility.

Catalog diagnostic `sourceId` is optional, but when present must be a UUID before the view may copy it or construct a source route. Missing attribution is a valid sparse outcome. Malformed supplied attribution rejects the response rather than producing a misleading link; this does not make optional publisher display labels mandatory.

CatalogRecord checks its existing EvidenceSet before local assessment/handoff is rendered, reusing the evidence predicate and exact validation/trust/legal-rights states. IndexedCatalogSearchEvidence checks the observation-group identity, at most sixteen unique source UUIDs and the same-source conflict flag. Optional/sparse attribution stays explicit; unknown evidence fields and exact raw downloads remain unchanged. These consumption checks do not create local assessment of external entries or whole-schema validation.

ObservationSearchResult checks its existing Observation, bounded score and source UUID before diagnostic links/rendering; optional kinds and structural/profile compatibility are consumed safely. LiveSearchResponse separately checks bounded results and its own diagnostic enum (including succeeded), preserving arbitrary entry evidence. Its optional version string may be omitted for an explicitly empty version by the backend serializer; versionPresent remains authoritative. These are consumption checks, not new whole-schema validators.

Live diagnostic rows also require a positive safe source revision and an exact lowercase SHA-256 digest. Assessment selection checks matching identifier/version presence, native media type and exclusive URL/data delivery. Indexed selection uses the current Source revision and an explicit raw read; the backend checks current complete-snapshot membership. Browser serialization never establishes the entry digest. FederationSource checks its optional named trust policy before an editor consumes it.

Private assessment results use their dedicated `sources.read` ceiling and explicit audited reads, not generic Jobs' `catalog.read` scope. The owning `trust-result.ts` guard checks the consumed nested check states, validity, bindings, applicability and bounded canonical base64. The screen verifies the exact entry bytes before display and downloads. It never interprets a succeeded Job as positive verification or fetches arbitrary evidence URLs.

The configured publication-host read is classified as a screen interaction. Its consumed-value guard checks the 64-item ceiling, bounded host text, unique choices and exact discovery modes before rendering the selector; this is not an ARD endpoint or a health check. Generated declarations and the Go host allowlist derive from the same updated Control contract.

`processInfo()` reads the fixed local `/_status` route. It validates UI build identifiers, role, UUID, timestamps and nonnegative whole uptime before use, with the same session fencing as `buildInfo()`. `buildInfo()` retains the unchanged static `/_build` contract. `ServiceInformation` validates the corresponding authenticated API observation. Neither check infers elapsed uptime by subtracting wall-clock timestamps.

`definitions.ts` derives every component kind/name from the loaded document, preserves exact pointer escaping and code-unit ordering, and filters the full index before local paging. Unsupported component collections keep a complete-data entry. Operation/definition anchors preserve their existing ordinary encoding; malformed Unicode has a separate safe encoding. Definition bookmarks must resolve an own local pointer, including composed-schema array elements and false/zero/null targets; unknown anchors confer no selector or network authority.
