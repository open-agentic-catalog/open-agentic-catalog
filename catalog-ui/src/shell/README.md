# Session and navigation shell

Development sign-in labels/descriptions come from the validated host options; React does not own a role roster. Stable `data-login-alias` attributes select configured identities in browser fixtures while permissions remain the sole navigation/action hints. The shipped profiles preserve six personas and add fourteen exact-template identities; descriptions and scrollable choices must remain usable at 320px and with the keyboard. Production OIDC retains its separate provider entry.

`App.tsx` owns login state, identity-change invalidation, route selection, lazy workflow imports and appearance preferences. Screens receive the shared workspace context and report failures back to the shell for current-access reconciliation. Keep session changes responsible for discarding private state, including late responses and cross-tab sign-out notifications.

`navigation.ts` supplies five sidebar groups and the Account destinations, existing per-link permissions, fixed page titles and parent breadcrumbs. Stable keys and placement select the UI location. Grouping is not an authorization boundary: retain specialist and create-only links without requiring Reader or tenant administration. Native links preserve document navigation and editor unload protection. Titles and breadcrumb labels must not include private names, identifiers or query text. Exact tenant/grant context belongs in My access.

The shell adds one Documentation link to Help before API reference when the host supplies a validated destination. Only the exact `/docs/` fallback or a credential-free HTTPS override is allowed. This policy is separate from resource metadata links. Documentation and Operator documentation open a new tab with `noopener noreferrer` and an accessible announcement. Account does not duplicate the link.

Unified Catalog navigation accepts local-read or external-discovery availability; local Explore needs local-read availability. Any-scope hints do not authorize writes in an arbitrary namespace. The independent `/my-feedback` route admits humans with `feedback.own` and its read scope, including those who have lost resource access; `/feedback` admits moderators separately. Keep these route and scope guards aligned with the owning views and Go host allowlist.

The sidebar orders Discover, Manage content, Operations, Administration and Help. Catalog is the first discovery link. Operations includes Service information for every signed-in identity. Search indexing remains a permitted anchor on that page. Personal pages use an Account breadcrumb and current-link indication.

The top-right Account disclosure contains the full subject, identity type, My access, permitted human activity links and Sign out. Its subject preview is bounded on wide screens. Appearance remains separate and available before sign-in. Both panels use native controls, ordinary tab order, Escape focus restoration and outside/focus-leave dismissal. Opening one closes the other. Account closes on a session refresh or replacement and disappears on expiry or sign-out. The existing leave confirmation and failed-sign-out recovery remain authoritative.

The narrow-screen header grows with its text and lets brand/environment labels wrap; keep Account and Appearance reachable when text is enlarged. Panels scroll within the viewport; narrow triggers keep their accessible names. The real browser accessibility regressions cover 200% text at 320px, including a wrapping Catalog result toolbar. Desktop navigation stays independently scrollable on short windows, and the Service indexing anchor belongs to that view rather than a second route.

Install only decoded host sessions. A current access refresh returning 401 or malformed self-context clears private state; a temporary transport/503 failure leaves the original operation denied and adds no permissions. Capture the client's identity signal across login, logout and refresh so superseded success or failure cannot change a newer session, its controls or notices. Refresh coalescing is per identity. Valid expired sessions remain signed out, and timer delays cannot overflow. `session-boundary.test.tsx` uses the real client with inert fetch replies to cover these decisions alongside the isolated shell-state tests.

`ErrorBoundary.tsx` supplies reload recovery when a render or deployment chunk fails. `Icon.tsx` holds local decorative SVG paths; surrounding text or an accessible control label supplies meaning. Do not add record-selected image fetches to the icon layer.

Route changes also affect the Go host's `clientNavigation` allowlist and workflow navigation tests. `app.test.tsx` covers shell/session interactions; `routes.test.tsx` exercises routed workflow selection; `error-boundary.test.tsx` covers recovery. Browser checks in the [test strategy](../../tests/README.md) own real focus, navigation and root/subpath behavior.

ANS assessments has its own Operations destination and `/trust-assessments/{jobId}?sourceId=...` bookmark. Opening it prepares exact lookup without reading evidence. It requires `job.read`, `source.read_evidence` and the `sources.read` ceiling, independently of the generic Jobs or Source pages. Private results and object URLs are discarded when access or identity changes.

Generic Jobs navigation also requires a readable tenant family (`source.read`, `source.read_evidence`, `publication.read` or `operations.reindex`) alongside `job.read` and enforced `catalog.read`. The shared `canReadJobs` hint does not assert matching targets exist. A direct route with no family shows access guidance without making a Job request; namespace/any-scope availability cannot replace tenant authority.

Search, local/indexed detail and Explore share one access-keyed Catalog owner. Its same-document history preserves bounded discovery context, including mode-specific Explore drafts; only captured indexed route identity drives detail reads. Read-only detail tags return to filtered discovery. The shell follows `popstate` for fixed page context/title without refreshing authentication or persisting private criteria. Ordinary links and authoring navigation keep native unload protection; do not extend this exception into a generic router.

`DiscoveryWorkspace` also owns an explicitly opened saved search through local/indexed detail navigation. Library criteria stage once; a new item, access identity or document replaces that workspace. Catalog consults the shell's synchronous navigation event before a refused Back/Forward action can unmount an editor. Only a numeric ordinal enters history. Consented return rereads applied criteria; revocation disarms execution. The search workspace has one page heading and one owner for text, layout, paging and consent.

`Bootstrap.tsx` renders runtime-loading progress before any authenticated client exists, rejects malformed settings and exposes explicit Reload. `App.tsx` owns separate login-options loading/retry state tied to the current client lifetime. Explicit login/logout focuses the visible page context; automatic session invalidation only replaces focus when its old target disappears. The absolute-expiry warning is keyed by the known expiry, so an ordinary access refresh does not repeat it.

About, Getting started and Troubleshooting are public after valid bootstrap. The host allowlist admits their exact root/subpath routes. Authenticated About requests build observations; Troubleshooting loads bounded build facts only after Preview diagnostic details. Private previews and recent safe response correlation clear with the current client identity. `QuickNavigation.tsx` uses a native modal, permitted fixed navigation entries and normal links; Ctrl+K/Command+K must not intercept editable targets or another dialog. Policy changes remove stale choices; an unchanged access refresh keeps focus and input.

Development sign-in uses `SignInChoices` with host-owned profile groups and typed presentation flags. It preserves explicit selection, public search/counts, native keyboard controls and the complete configured roster. The presentation describes seed intent; current permission checks never depend on it.

Feedback and rating list/detail links also use bounded same-document navigation. Only a navigation ordinal enters history. Each view retains one list context in memory, clears it with the full access key and rereads the returned page. The shell consults their synchronous Back/Forward guard before replacing the route. Direct case routes have fixed Feedback case/Rating case titles; IDs and comments never enter document titles. The host admits only UUID-shaped case detail segments.

OIDC sign-in shows one Sign in button. Callback notices come from a fixed host-code vocabulary; query values never establish identity or control navigation. Provider failures, Catalog refusals and expiry have separate messages. Development identity choices remain limited to development mode.
