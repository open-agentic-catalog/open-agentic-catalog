# UI host boundary

Package `web` serves one configured browser deployment. It has no database access. `config.go` validates closed startup JSON, exact deployment URLs and mounted inputs. `server.go` validates local assets before readiness, dispatches browser routes, applies origin/admission checks and manages local drain state. Root health endpoints do not call the API or issuer.

`documentation.go` serves the immutable manual at the fixed `/docs/` route, before UI base-path dispatch. It checks bounded build evidence and regular files at startup. Requests use the admitted inventory and an `os.Root` to contain file access. Missing files return 404s, without SPA fallback. The public route reads no session or API state. It has a separate hashed CSP, same-origin search/WASM support and explicit cache policy. Source fixtures can omit the bundle; malformed present bundles fail startup. Image inspection verifies the complete inventory and hashes. `/docs` and its descendants cannot be UI base paths.

Current-session reads obtain fresh Catalog access, retain absolute session expiry and never expose the bearer. The separate 64 KiB self-context limit rejects oversized responses before parsing, including valid JSON prefixes followed by excess bytes.

`session.go` authenticates and encrypts cookies bound to the deployment and absolute expiry. `oidc.go` owns development selection and OIDC code/PKCE login, requiring API-accepted human identity before issuing an OIDC session. Discovery authorization/token endpoints must share the configured issuer origin.

Pending state lasts five minutes independently of the session lifetime; login start refuses requests already carrying four pending-login cookies. Browser callback failures return to the local sign-in screen with a fixed error code. JSON clients keep their existing problem status and envelope. No provider text, authorization code or callback state reaches the retry URL. Callback preflight rejects unbound or expired state before provider requests and clears validated pending state before continuing. `transport.go` isolates API and issuer trust/connection pools, confines each client to its configured origin and bounds responses.

The transport closes the original upstream body before returning buffered bytes or a response-validation error. These fixed destinations are distinct from the backend's metadata fetch boundary.

`proxy.go` derives allowed product methods and paths from embedded OpenAPI, forwards only selected headers and substitutes the session bearer. It preserves API response bytes and validators, passes 304 responses and refuses redirects. Local product `Location` values are rewritten beneath the deployment's `/_catalog` path; absolute, non-product and backslash-containing locations are omitted. `reference.go` obtains the connected API contract for read-only browsing and exact download, enforcing independent 1 MiB source and 4 MiB JSON projection limits without fetching external references. Keep browser-supplied destinations, authorization overrides and worker operations outside these routes.

When changing this boundary, run `go test ./catalog-ui/internal/web/... ./catalog-ui/cmd/catalog-ui/...` from the repository root for isolated handler/configuration tests. Add `-tags=functional` for API/issuer exchanges, readiness probes, membership workflows and real zero-contact assertions. Also run the applicable [UI security/browser tests](../../tests/README.md). Preserve negative cases for origin checks, key rotation, response bounds, redirects, current membership and retained private evidence. Host configuration and deployment procedures remain in the [UI guide](../../README.md).

Fixed-transport units register in-process handlers on fresh transports and deny socket access. They check destination refusal, bounded reads, issuer JSON policy, sanitized failures and original-body closure. Real TLS, redirects, connection reuse and readiness probes belong to functional verification; these units do not establish connection reuse.

Local OIDC-constructor units check missing/blank secrets, trimmed-secret loading and issuer-trust error propagation with temporary files. Direct development-login units reject unknown aliases before API access and check API denial/unavailability with controlled transports, fixed public errors, no session cookie or redirect, and released admission. Existing successful login/session-size units supply controls; real mounted-input zero-contact, issuer exchanges and complete login workflows remain functional assertions.

Constructor units also check configuration rejection before mounted-file loading, development-user count/alias boundaries and token-free login options. The direct route matrix uses valid authenticated session/reference reads as controls for method refusal, checking that rejection consumes no body, contacts no upstream, changes no cookie or redirect and releases admission.

`New` receives the process-owned logger; a nil logger discards diagnostics for isolated callers. `diagnostics.go` observes each final host response without retaining its body. It owns fixed route families, bounded dependency warnings, operation-scoped recovery and DEBUG authentication/session outcomes. It generates or validates local correlation and independently validates upstream response IDs; browser correlation headers are not forwarded to API/issuer clients. The [observability runbook](../../../documentation/src/content/docs/operations/observability.mdx#ui-host-events) defines fields, severity and limits. Issuer observation wraps the existing fixed transport without changing its origin, redirect, trust or deadline policy.

`/_status` returns this UI process's build, role, execution ID, UTC startup/observation times and monotonic uptime. It shares `/_build` origin and drain admission, rejects queries and does not contact upstream services. It does not require a session for these process-local fields, matching the existing static build boundary. The browser presents it on authenticated Service information. `/_build` remains unchanged; the host owns no startup history or node registry.

Public `/about`, `/getting-started` and `/troubleshooting` client routes require no session. The fixed `/legal/LICENSE.txt` and `/legal/third-party-notices.txt` paths serve bounded regular text files from the browser build, including under a UI base path. Unknown files, queries, non-read methods, links and missing files fail explicitly. No directory, image filesystem license tree or arbitrary path becomes public. Browser notices preserve original runtime JavaScript texts; image Go/manual license inventories remain separately retained.

The exact public Help navigation allowlist also includes `/troubleshooting` at root and configured UI subpaths, including direct GET/HEAD reloads. Deeper unknown routes remain refused. Static guidance requires no API access; the browser's optional diagnostic preview uses existing authenticated service-information and UI-build reads, without a new host endpoint or diagnostic upload.

Development options expose only the fixed alias, bounded display text and explicit `profileGroup`/`elevated`/`separateTenant` presentation fields. The host validates the finite group and typed flags without inferring them from role captions. Tokens stay private; these hints never affect identity or Catalog authority. OIDC has no development roster.
