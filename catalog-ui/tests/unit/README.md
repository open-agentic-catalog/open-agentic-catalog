# Shared component fixtures

`fixtures.ts` provides a typed reader context, explicit deferred promises, a transport substitute and jsdom's missing dialog-open behavior. `screens.ts` adds representative immutable record relationships, ETag replies, exact route stubs and screen setup/teardown. An unconfigured request is recorded and fails teardown even if the component catches its error.

`setup.ts` gives DOM workflows 15 seconds and asynchronous DOM assertions 5 seconds. Logic-only files retain the 5-second Vitest limit. These bounds allow slow CI runners to complete real render and accessibility work. Test data, assertions and coverage thresholds stay the same. Fake-timer controls verify that delayed controls can appear and missing controls still time out.

Only transport and missing DOM primitives are substituted. Keep component permissions, validation, command preparation and recovery behavior active in tests. Settle deferred responses explicitly to exercise identity and unmount races. Do not use these fixtures to claim real focus trapping, layout, TLS, PostgreSQL or browser behavior; those checks belong to the [browser fixtures](../browser/README.md) and the [UI test strategy](../README.md).

Unit and component tests stay beside their source under `../../src/`. Reuse these helpers when their exact request/teardown contracts fit, and keep workflow-specific records and expected payloads in the owning test.

`review-publication-ui.test.tsx` checks publication preparation with injected GET/POST replies. Reload cancellation preserves a supersession draft; confirmed reload clears it when current readback has no release pointer, and the next command uses the new ETag without the discarded reason. A publisher without metadata permission can supersede an uninspected prior release and deliberately read permitted history without a Listing metadata request. These cases use jsdom and an injected confirmation result, with no application binary, listener, network or database. The browser suite separately qualifies real commit, retirement and replay.

Snapshot units use inert values in `publication-fixtures.ts` and the same injected transport. They cover active-read failures, exact comparison context, duplicate ordering, absent/empty versions and command recovery during inventory filtering. All four comparison sections page independently across 25/26 entries without more API calls. Deferred baseline and selected-snapshot replies cannot replace a newer explicit comparison. Scrollable-table units substitute dimensions and resize notifications; they do not measure browser layout. No fixture starts a listener, executable or database. The browser and PostgreSQL selections qualify their respective real boundaries.

Publication inventory tests check accessible cells once, then read native table rows to verify order. Both complete 28-entry documents retain their sorting, pagination, close/reopen and independence assertions. Authoring tests scope queries to the active field group or Listing panel. Validation tests load real lazy modules before rendering, while browser tests cover chunk loading. The continuation unit explicitly settles its delayed Publisher reply and checks the preserved selection, returned ETag and exact command count. These units retain real components and scripted transport without sleeps or automatic retries.

API-contract copy units use inert clipboard promises and local declarations. Independent literal expectations pin decoded JSON and the 65,536/65,537 UTF-16 boundary, including supplementary Unicode whose byte/code-point counts differ. The refusal/retry case preserves exact path placeholders and safe feedback without an automatic retry. It starts no application binary, process, listener or database. Actual permission denial and operating-system clipboard contents belong to `../browser/reference-contract.spec.ts`.
