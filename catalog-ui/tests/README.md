## What coverage means

The Go command's functional tests separately exercise occupied-listener cleanup, real HTTP serve/drain behavior and a temporary UI executable's missing-configuration diagnostic and exit status. `make coverage-profile` captures the selected child-process counters and includes them in the Go local profile; `make coverage-full` includes that profile in its application union. These counters do not change the frontend Vitest percentage or replace browser assertions.

A packaged reader search is compared with `catalogctl remote search` against the same approved federation fixture. It checks indexed/live provenance and version presence, distinct indexed continuation, inert metadata previews and partial results during upstream failure. Core, hybrid and live-only continuation preserve one unchanged bounded live window. Browser retry retains displayed cards and resubmits the same token. The CLI uses the Control API; this does not qualify a commercial assistant or a native MCP connection.

Separately, `make test-federation-peers` runs [peer-journeys.mjs](../scripts/peer-journeys.mjs) against two owned PostgreSQL-backed Catalogs. It builds the normal UI host and assets, publishes 25 temporary Agent releases, and crosses the normal 24-card page size. Real peer outages check retained cards, disabled Next, exact-token Retry and First page recovery. Mixed-origin pages check the complete identity set in core and PostgreSQL hybrid modes. A fixed-vector provider tests ordering and continuation, not relevance. These journeys supplement the ordinary browser suite and do not collect Istanbul source coverage. See the [peer harness](../../test/functional/README.md#two-catalog-federation) for prerequisites and cleanup.

A workflow is covered when the browser performs an action with an appropriate identity, checks its outcome and verifies saved state through a reload or subsequent read. Opening a page, setting up data through the API, seeing a request or taking a screenshot is not a substitute. Successful mutations reach the real API; deliberate intercepted failures test client recovery only.

The namespace read journey injects a 429 with an HTTP-date hint, advances browser time beyond that date without another request, then rejects excessive 503 advice before explicit reload recovers real results. The existing edit/stale-revision journey replaces one committed update response with a hinted 503, then checks explicit replay of the exact method, URL, body, key and real `If-Match`, unchanged committed ETag, and the original stale-editor 412 denial.
