# UI process entry point

`main.go` handles `version`/`--version`, `--help`, the `--probe` readiness check and standalone host startup. Startup requires `--config /path/to/ui.json`. The binary reads that strict JSON file and no environment overrides; launchers can generate the file from their own variables. See [UI host configuration](../../../documentation/src/content/docs/reference/ui-host-configuration.md) for all settings and mounted inputs. Version output is JSON and loads no configuration. The probe targets only `http://127.0.0.1:8080/readyz`, ignores `--config` and does not check the upstream API or issuer. Host construction validates mounted configuration, key material and built assets before opening the listener. Signal handling marks the host unready, stops new authenticated admissions and drains the listener within its shutdown bound.

Keep HTTP behavior in [the web package](../../internal/web/README.md); this command owns flags, listener limits, signals and process exit status. The blank fallback-root import belongs to the static binary's TLS trust packaging. Build and local/container instructions are maintained in the [UI guide](../../README.md). `make ui-build` writes the host at `bin/catalog-ui` and browser assets at `catalog-ui/dist/`; `make build` builds only the backend. The [command reference](../../../documentation/src/content/docs/reference/commands.md#optional-ui-host) covers supported invocation modes.

[Command units](main_test.go) check local validation, listener handoff, error sanitization and shutdown decisions with an inert listener. [Functional tests](main_functional_test.go) invoke `run` against an occupied loopback address in a bounded test-binary subprocess, then separately exercise real HTTP readiness and graceful shutdown through `runHost` and `serve`. They require the sanitized startup error, retained collision holder, drained readiness and a reusable listener address before test cleanup. These tests do not deliver OS signals or exercise `main`/`os.Exit`; packaged probes and browser journeys retain their own scope. Run `go test -tags=functional ./catalog-ui/cmd/catalog-ui -shuffle=on -count=1` from the repository root, or `make test-ui` for the complete UI gate.

Command and flag failures use reviewed output without private argument values. The HTTP listener has safe fallback logging and a panic wrapper that aborts incomplete responses. Listener panics drain the host and return a fatal marker; simultaneous cancellation cannot turn them into success.

Terminal failures use the configured text/JSON format on stderr, with fixed structured text before configuration is trusted. Startup logging controls and bounded lifecycle/upstream events are implemented. See the [host event policy](../../../documentation/src/content/docs/operations/observability.mdx#ui-host-events) for fields, severity and limits.
