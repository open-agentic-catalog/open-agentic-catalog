# UI build and test tooling

These Node scripts support the independent UI toolchain. Invoke the root Make targets or UI package scripts so required binaries and browser assets are prepared in order; see the [UI guide](../README.md) and [test strategy](../tests/README.md).

The packaged TLS proxy and documentation fixture use the shared dynamic/private port allocator. The host ephemeral range can include browser-blocked ports. Browser security settings stay enabled.

`packaged-test.mjs oidc --local-passwords`, exposed through `make test-local-auth`, selects `local-password-journey.mjs`. It exercises the real one-Catalog launcher instead of constructing another realm. It checks regular sign-in, exact grants, provider account changes, suspension, outages, restart, TLS renewal and CLI PKCE. Synthetic credentials stay in private inputs and browser memory. Safe reports and empty-field screenshots stay in ignored output. Cleanup verifies that its project has no remaining containers, volumes or network. Prerequisite-refusal units use injected commands; actual browser failure cleanup has separate qualification.

SIGINT and SIGTERM produce a nonzero exit status. Cleanup continues if browser shutdown fails. Further signals do not cancel cleanup commands. A completed report can precede a final cancellation; check the command's exit status too.

Fixture helpers must not attach to an existing service, inherit ambient Catalog configuration or clean up another process's listener. Retry bounded readiness reads only; browser command failures remain visible. Keep tokens, cookies, private request bodies and raw provider/engine output out of test diagnostics. Adjacent `*.test.mjs` files verify these tooling boundaries using Node's test runner.

The packaged supervisor owns SIGINT/SIGTERM and disables Chromium's competing handlers. Deferred task rejections fail the runner and unwind its workflow through owned cleanup. Repeated failures do not kill cleanup commands. The explicit [interruption qualification](../tests/browser/README.md) exercises actual images, Chromium waiters and failure cleanup separately from ordinary Node/React tests.

`dev-documentation.mjs` stages a selected prepared `/docs/` bundle for `dev.mjs`. It copies only admitted regular files, verifies byte sizes/hashes and keeps the source unchanged. The host performs complete metadata/CSP validation. The launcher removes its private staged assets on exit. No documentation toolchain is needed for ordinary source tests.

Source/input inventories, mutation input hashes, combined profile names and package/notice paths use explicit JavaScript code-unit ordering. Preserve that exact ordering when comparing or hashing inputs; locale collation can consider distinct spellings equivalent. License entries compare their path keys directly without converting package metadata to strings. Existing source-bound checks, native ordering regressions and the actual mutation/browser/image gates qualify these boundaries.

[Dead-code functional tests](dead-code.functional.test.mjs) qualify the installed pinned Knip and `../knip.json` using bounded temporary projects. They execute real analyzer/Make/npm processes, preserve maintained source and do not start application/browser fixtures. The report/check commands use native CLI behavior directly from package scripts; no custom reachability runner is needed.

`authorization-evidence.mjs` supplies fixed method/route-bound refusal categories and recognized Control error codes to the native fixture and shared authorization journey. It preserves the setup error's status/code text used by negative journeys. `rotation-evidence.mjs` selects bounded, request-correlated backend/UI diagnostics, including only the reviewed operation stages. Unknown stages and private details are omitted. Adjacent unit tests check these exclusions and the setup-error contract. Group-member revocation has its own exact method/route/detail category without claiming a time-only cause. `search-continuation-evidence.mjs` classifies only reviewed HTTP status/code/detail combinations for retry and later-page refusals. Browser assertions still require success; unknown bodies remain unclassified and no query, cursor or private detail is logged.

The packaged authorization journey calibrates invocation-owned, read-only scalar PostgreSQL projections against successful group transitions and its first successful assignment revocation at each hosting path. On an unexpected refusal it retains state/revision/receipt booleans, retained command-response status and the bounded correlated diagnostics under the owned ignored output directory. It does not retain target IDs, command keys, request contents or raw SQL errors, retry the mutation or replace the original failing assertion. Reservation-start ordering and state-or-time refusal categories do not establish the attempted transition time or a time-only cause. The fixed backend time-regression stage identifies the actual failed comparison. The same optional callback is declared in `authorization-journey.d.mts`.

After an exact role-update state-or-time refusal, the local browser fixture makes one authorized read of that same role. It reports only a fixed state, revision comparison and clock comparison, without names, permissions, timestamps or credentials. The clock comparison accounts for HTTP Date's whole-second precision: it is positive only when that entire response second precedes the saved update time. Failed readback remains unknown and the original command still fails. The archive browser control uses the same safe refusal classifier and independently verifies saved state/revision after success. These diagnostics neither retry mutations nor relax chronology guards.

The ordinary browser fixture can select `curated: true` to seed the maintained twelve-release sample. It prepares owned TLS archives from local assets and validates a bounded allowlisted ZIP before seed readiness. This option cannot combine with synthetic archive/artwork modes. The original synthetic ZIP/document oracle remains unchanged. No fixture executes a resource or contacts hosted sample destinations.

`browser-fixture.mjs` accepts an explicit boolean `publicationAudiences` only for publication-content journeys, adding authenticated primary-tenant and empty secondary-tenant hosts to its private owned configuration. Ordinary fixtures do not gain those hosts. Packaged journeys follow source Job results into their exact retained snapshot and inspect readable delivery outcomes while preserving actual worker/receiver assertions.
