# Safe diagnostic boundaries

Command reporters use [reviewed error projections](../../safeerr/README.md), fixed operation/code/type fields and one terminal record. Service failures use the selected text/JSON format on stderr; operator errors use concise text, preserving stdout results. Flag parsing suppresses implicit diagnostics containing supplied values; explicit help prints declared names and guidance without environment-derived defaults. The remote CLI retains its separately sanitized JSON error shape and silent parser: its own writer emits one fixed help response, so it does not use the generic help-emitting parser.

Every owned HTTP listener installs an explicit standard-library logger that emits a fixed ERROR without retaining raw transport text, peer addresses or panic stacks. The API retains its transactional request recovery and request-ID correlation. The worker operations and UI host wrappers abort a panicked response, including an already committed response, without appending a second body or logging `http.ErrAbortHandler` twice. The fallback remains an observable failure rather than a discarded log stream.

The three command entry points install `ProtectStandardLog` before command dispatch. It replaces unstructured standard-library/dependency text, including Go HTTP/1 unsolicited-response bytes, with one fixed `dependency.diagnostic` WARN per warning window. It never parses or retains that text. Bootstrap uses stderr; `Startup` binds the effective process logger, preserving service stdout, operator stderr, configured format and filtering. Only command entry points install this process-wide safety adapter; constructing a library logger leaves both default loggers untouched, and the adapter never replaces `slog.Default`. Direct writes to stderr and runtime crash output retain the documented limits.

Tests separate isolated reporter/handler behavior from real HTTP and compiled-command cases in the owning commands. Startup configuration, backend event consistency and UI dependency/session events are implemented. The UI executable regression receives a valid API self-context followed by unsolicited private bytes, preserves successful login and verifies safe output and filtering in both formats. This package adds no logger framework, collector, file sink or runtime setting.

`ValidateLogging` and `NewLogger` share only strict vocabulary and standard synchronous `slog` construction between backend and UI; no backend configuration dependency enters the UI. `Startup` projects bounded selected settings/build identity and identifies injected handlers. `WithFormat` preserves error identity while carrying a validated service format to terminal stderr output; failures before configuration retain text fallback. Operator command errors remain concise text independently of runtime log format.

`Process.Logger` derives a child with bounded service/role/environment/version fields; the configured handlers normalize timestamps to UTC. Call sites own fixed event/component values and numeric duration units. `Warning` holds one fixed call site's first/once-per-minute warning state and suppressed count, emitting outside its mutex. It has no dynamic keys, background task or effect on metrics.
