# Bounded metrics and diagnostics

[registry.go](registry.go) owns the process registry, fixed label vocabularies, lifecycle/component state and bounded text rendering. [runtime.go](runtime.go) maps service workflows and database observations into that vocabulary. [webhooks.go](webhooks.go) defines bounded delivery aggregates, while [tracing.go](tracing.go) records exporter outcomes without exposing SDK errors. [security.go](security.go) counts final API authentication/authorization refusals using two fixed reasons, independently of log filtering. Embedding operation histograms include local admission and rejection; they are not provider-request or token counters.

Request paths, tenant/resource identifiers, query text, URLs and raw dependency errors must not become labels. Runtime collectors return bounded operational projections; they do not make an optional receiver a process liveness dependency. [HTTP](../httpserver/README.md) and [worker operations](../operations/README.md) choose which health and diagnostic projections to expose.

Run `go test ./internal/platform/observability -shuffle=on -count=1` for label admission, concurrent updates, rendering bounds and safe degradation. The [observability runbook](../../../documentation/src/content/docs/operations/observability.mdx) owns operator-facing metrics and health semantics.

[retries.go](retries.go) records Job and webhook scheduling only after the owning store accepts a waiting transition. Histograms measure the saved due time minus the saved completion time, including accepted hints and jitter. They are process-local observations, not actual queue waits or durable audit counts. Buckets cover zero through 24 hours; Job kinds use the existing fixed labels, and webhook schedules have no receiver labels. No optional collector is required.

Production composition shares `processinfo` with the registry. Startup and uptime metrics use that execution's start and monotonic elapsed time. `New` retains the injectable wall clock for aggregate timestamps and existing isolated tests. Compact service-information reads use `processinfo` directly; they must not call `Snapshot` or its database providers just to obtain uptime. No instance ID is added as a metric label.

Service activity uses the fixed [HTTP populations and sample fields](../../../documentation/src/content/docs/architecture/decisions/0021-logging-observability-and-audit.md#service-activity-measurement-contract). The default-off HTTP endpoint requires explicit deployment disclosure and current tenant-wide `access.manage`. Enforced OAuth scopes also require `tenant.admin`. The Activity tab at `/overview?view=activity` shows exact counters and compatible interval rates. Refresh is manual by default. Optional live refresh pauses when the tab is hidden or a read fails.

The API records fourteen fixed request families through `BeginHTTPFamily`. Worker operations use `BeginHTTP` and remain auxiliary, including patterns shared with the API. `Activity` copies fixed counters under the registry lock without provider callbacks. The separate active-Catalog gauge excludes probes, scrapes, observation polling and auxiliary traffic. Existing Prometheus series keep their names and populations.

The [HTTP qualification tests](../httpserver/service_activity_population_functional_test.go) wait for completed middleware accounting before comparing snapshots. Receiving a response body alone does not establish middleware completion. These waits never repeat the HTTP request. Isolated registry tests cover coherent copies, exact counters and concurrent duplicate completion. Real HTTP tests cover routing, current authority, read side effects and separate HTTP/Search/MCP populations.
