# Optional tracing adapter

This package owns the official OpenTelemetry SDK and OTLP/HTTP protobuf exporter. Domain packages depend only on `catalog.Tracer` and its private `TraceContext` value. `catalogd` explicitly starts tracing; configuration inspection and operator runtime construction do not. There is no process-global tracing provider or propagator.

`tracing.go` implements process resources, sampling, safe spans, bounded batching and shutdown. `inputs.go` validates deployment-injected authentication/trust files. The exporter uses the separate endpoint-bound client in `../fetcher/telemetry.go`; its private-network and header permissions never apply to normal federation or webhook fetches.

Keep span names/outcomes code-owned and attributes allowlisted before SDK recording. Never record errors, panic text, headers, SQL, identifiers or documents as attributes/events. SDK diagnostics are replaced by a sanitized process hook; only bounded export counters and rate-limited fixed messages leave that boundary. See the [tracing runbook](../../../documentation/src/content/docs/operations/observability.mdx#distributed-tracing) and [configuration reference](../../../documentation/src/content/docs/reference/configuration.mdx#optional-tracing-configuration).

Run `go test ./internal/platform/tracing -shuffle=on -count=1` for isolated tracing tests. Use `go test -tags=functional ./internal/platform/tracing ./internal/platform/httpserver ./internal/platform/fetcher` for local boundary exchanges, `make test-integration` for immutable causal metadata, `make test-tracing` for owned Compose and `make test-minikube-tracing` for cross-process Helm qualification.

Unit tests keep input validation and span behavior independent of collectors. `inputs_test.go` covers bounded authentication values and safe credential/trust failures; `concurrency_test.go` covers request isolation, producer parentage, unlinked attempt roots, safe outcomes and sampling entropy failure. `attempt_test.go` covers linked attempt roots, client children and safe outcomes, including Error status for exhausted/unsupported Jobs; `exporter_test.go` covers fixed export errors, submitted-batch accounting and concurrent warning suppression through a controlled exporter. The shutdown units cover both success and failure with idle-connection cleanup. `tracing_test.go` and `failure_test.go` retain projected inputs, disabled startup, direct sampling and malformed secret/trust parsing. Certificate parsing uses generated bytes without a listener.

Mounted TLS units also verify independently signed trust chains, matching client-key possession, preserved public roots, multiple private roots and rejection without partially usable credentials. The enabled zero-sampling constructor unit uses `testing/synctest` for idle batching and shutdown, ending only confirmed unsampled spans and observing zero exports. Source review of the pinned SDK establishes that this constructor/empty-shutdown path makes no requests; it does not qualify collector delivery. Recheck that assumption when updating the exporter, and keep sampled export and TLS exchanges functional.

`tracing_functional_test.go` and `failure_functional_test.go` retain real loopback HTTPS export, mTLS, configured sampling, bounded queue/shutdown and collector failure behavior. The fetcher's `telemetry_test.go` retains injected DNS and header-policy units; `telemetry_functional_test.go` checks request bounds and the exact endpoint with a real receiver. Add cases at the owning boundary rather than duplicating full Compose journeys.

`mtls_functional_test.go` uses a collector with `RequireAndVerifyClientCert` and a dedicated client CA. The listener in `mtls_fixture_functional_test.go` retains typed handshake failures before HTTP admission. Tests bind each rejected leaf to its actual certificate and require zero OTLP handler calls. They cover absent, unrelated, expired, not-yet-valid and wrong-EKU clients, successful export, certificate/key replacement, server trust replacement and retirement of each old authority. Every export uses a fresh connection. These are local TLS tests, not pure units or a new application health check. No host time or revocation service changes.

The disabled-path benchmark remains untagged: run `go test ./internal/platform/tracing -run '^$' -bench '^BenchmarkDisabledTrace$' -benchmem`.

The provider never emits attempt completion logs. Job completion diagnostics belong to the runtime observer; webhook processing failures propagate to the supervisor. `LogAttributes` projects only valid active local SDK context, including sampled/unsampled decisions; retained causal metadata alone is not an active span. Incoming HTTP correlation/parenting shares one version-00 admission rule in the HTTP boundary.

The composition root supplies `New` with the execution ID captured by `processinfo`. The provider uses that exact value for `service.instance.id` and does not generate another identity. Process status and metrics remain available when tracing is disabled. Enabled construction rejects a missing execution ID before opening an exporter.
