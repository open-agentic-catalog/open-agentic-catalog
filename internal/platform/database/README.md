# PostgreSQL persistence

This package implements the domain repository ports against PostgreSQL 18. It owns SQL, tenant context, exact API/worker privileges, atomic command execution and bounded operator inspection. It does not run migrations during API or worker startup.

| Files | Responsibility |

| [migrate.go](migrate.go) | Checksummed forward migration planning/application and grant reconciliation under one advisory lock. SQL sources live in [migrations/](../../../migrations/README.md). |
| [semantic_schema.go](semantic_schema.go), [postgres_semantic.go](postgres_semantic.go) | Explicit optional pgvector setup, exact grants and tenant/profile/lease-fenced derived storage. |

Every tenant-scoped operation includes its tenant boundary. The worker's bounded global selection is deliberate; follow-up access still includes the explicit tenant predicate. Preserve forced RLS, exact same-tenant relationships, immutable history and role separation. New schema objects require deliberate manifest changes; do not grant broad DML to make a test pass.

Run `go test ./internal/platform/database -shuffle=on -count=1` for helpers and repository behavior exercised through fake transactions and rows, without connecting to PostgreSQL. These tests also run in `make test-unit` and `make test`. Real PostgreSQL tests stay in `*_integration_test.go` files with `//go:build integration`; fakes do not replace their SQL, RLS, constraint or transaction guarantees. `make test-integration` owns an empty disposable PostgreSQL instance and cleanup. Only `make test-integration-dsn` accepts a caller-owned disposable database; never select a retained development or shared database. `make bench-search` and `make bench-search-plans` provide separate opt-in diagnostics without replacing correctness tests.

Observation metadata queries select `octet_length(raw_entry_bytes)>0` instead of document buffers. This preserves exact-evidence presence and missing-evidence errors, without claiming a new digest verification or eliminating PostgreSQL storage work. Full `GetObservation` and bounded current-observation reads retain bytes for exact export, adoption and reconciliation. Indexed trust selection checks an exact retained occurrence in the source's current complete snapshot through a bounded `EXISTS` query. An observation's original snapshot does not establish its current provenance. Group occurrence summaries use one statement for at most 100 selected observation IDs; each exact count and latest tuple share its statement snapshot.

The ordering remains observation time descending, snapshot ID descending, retrieval digest and entry location in byte order. Missing selected evidence rejects the complete result. Exact history counts still scale with retained history; no new index, migration or privilege manifest is required.

Readiness units classify writable/read-only results and failed or partial scans through a private `QueryRow` helper. Standalone tenant-transaction units reuse `commandConnection` for option binding, tenant setup before callbacks, results after commit, failure stops and bounded rollback after cancellation or panic. The outer `withTenantTx` retains its concrete pool and tenant validation before joining an ambient command. Real session writability and transaction recovery remain PostgreSQL assertions.

Privilege units use the existing query and migration-transaction interfaces to check exact inventory differences, quoted grants, extension overloads, owner preflight, failure cleanup and verification before commit. Runtime admission units check direct-login decisions, API/worker acceptance, refusal after failed reads or privilege drift, and returned attributes through a read-only query helper. Fixtures describe query results; they do not establish effective PostgreSQL authority. Concrete-pool execution, actual session identity, grant/lock behavior and RLS remain covered by the real PostgreSQL suite.

Migration units check retained checksums, pending selection, SQL/ledger pairing, failure propagation and the handling of earlier commits. Lock-cleanup units use a narrow session stub to check unlock/close decisions, joined error causes and one cancellation-independent deadline. Optional-schema units check qualified extension references, owner preflight and verified repeat setup without writes. They use existing scripted transactions; real session-lock release and connection discard, migration/reconciliation ordering, DDL, ownership and RLS retain PostgreSQL integration coverage. The exact-role fixture also cancels public apply during an observed advisory-lock wait and rejects a missing runtime role after lock acquisition. Both failures preserve the migration ledger and exact grants, followed by a successful apply; a distinct session proves the failed role check released its lock.

Restore units check schema-result interpretation, inventory bounds, classified findings, query cleanup, feedback pagination and public input guards. Synthetic constraint/trigger projections never stand in for a valid PostgreSQL inventory digest. Public restore/audit snapshot transactions, actual catalog predicates, exact guard definitions and read-only guarantees retain integration coverage. Both readers are also canceled during an observed table-lock wait after their transaction starts; they must return an empty report with an error, release their transaction, preserve retained rows and allow subsequent verification through the same pool. Audit encoding and trusted-manifest semantics remain in the audit package.

Feedback, publication and notification repository units use static records, retained snapshots and the existing scripted transaction/coordinator helpers. They check tenant/host and limit arguments, row cleanup, transaction intent, valid state/evidence handoff and failure propagation. These fakes do not execute SQL, enforce RLS, prove rollback atomicity or update durable loss counters. Existing integration tests retain those assertions.

Publication snapshot summaries intersect tenant, host, cursor and optional exact state in SQL before the generation/ID ordering and limit. The existing exact API-role integration workflow checks an older active generation behind a newer retired generation, filtered continuation and empty candidate/foreign-host/foreign-tenant controls. Existing state columns, indexes and runtime read privileges suffice; this read filter adds no migration or manifest grant.

Catalog collection units check bounded selection before two metadata queries, omitted document fields, retained retrieval bindings and row cleanup. Exact record/publication reads retain full Skill and Plugin evidence checks. Audit-export units check selection before hydration, aggregate byte limits and evidence handoff. Combined search units check that local/indexed reads request one repeatable-read transaction; PostgreSQL tests still qualify snapshot consistency under concurrent writes. Direct-pool outbox claim and lease methods retain their integration boundary.

Publisher integration tests call the repository directly with stale update and publication-domain revocation revisions, preserving publisher authority, a real release and evidence. A fixture-scoped audit-insert failure must roll back a valid update; retrying after removing the failure commits exactly one publisher change and its audit/outbox pair. Existing domain approval/removal and cross-tenant publication assertions remain in the same workflow.

Mutation-evidence integration tests use the existing disposable schema and exact API role for draft deletion and publication-domain approval/revocation. Triggers scoped to the operation's tenant, target, action and evidence ID reject inserts after checking the intended state change; outbox rejection also requires the preceding audit row to be visible in that transaction. Rejection preserves both tenants' objects and evidence. Retrying the same IDs commits only the expected mutation and one audit/outbox pair. These repository cases preserve the separate command-level host-withdrawal and release tests.

Federation units check bounded source selection, observation provenance, snapshot/occurrence history, indexed search and audit/notification handoff using the reconciled withdrawal count. Source revision audience/referral bindings and failure cleanup use the same scripted transactions; remote source behavior remains separately qualified.

Access units use the same coordinator for scoped membership and grant changes, final-administrator guards and evidence failures. Operator realm units exercise existing transaction helpers and preflight only; direct-pool identity resolution and operator role/commit boundaries retain real PostgreSQL qualification.

Idempotency, search-repair and identity-provisioning authority units share a table-owner matrix through narrow `QueryRow` dependencies and existing scripted rows. They check exact current-user/table-owner matching, rejected runtime roles, missing tables and failed or partial scans. Only a successful idempotency authority read returns its database actor. Existing nil-pool preflight, plan, digest, audit and progress tests retain their scope; actual role ownership, tenant enforcement, advisory locks, index validation and committed repairs remain PostgreSQL assertions.

Search-repair integration tests reject a valid-but-absent tenant and a fixture-scoped repair audit insert. Both failures preserve observation projections and immutable source bytes, search generation and evidence; the existing bounded repair succeeds after the injected failure is removed. Exact-index, runtime-role denial, empty-tenant and cross-tenant search checks retain their separate assertions.

Repair-read units use the existing `commandConnection` boundary to check read-only options, tenant setup, exact reservation binding and error handoff. A commit failure can accompany a decoded record; callers must check the error before using it. Scanner and short-transaction units keep their existing matrices, while advisory-lock and complete plan/apply workflows remain integration coverage. The crash-recovery fixture holds a competing command lock after planning, requires apply to refuse before its deadline, and checks the entire pending reservation, execution binding and absence of repair evidence. Releasing the lock permits the same plan to succeed before the existing command retry and replay checks.

Webhook key-maintenance integration tests cover missing-tenant rejection and refusal while another transaction holds an endpoint write lock. Refusal must precede the operation deadline, preserve ciphertext and endpoint history, and leave audit/outbox counts unchanged. The existing bounded replacement, resumable traversal, exact signing-secret preservation and audit-failure rollback cases qualify progress after the lock is released. The table lock does not establish that worker reads or sends are stopped.

Atomic-command handoff units exercise reservation results, callback context and audit attribution, exact response bindings, abort hooks, failed completion and panic cleanup through the existing command coordinator and scripted transactions. Pool acquisition and advisory-lock release remain in the public wrapper; incomplete execution aborts before control returns to that lock owner. Existing reservation and transaction-lifecycle units retain their decision matrices. PostgreSQL tests qualify SQL ownership predicates, real exclusion, atomic persistence, cancellation and crash repair.

Job API List/Get use [metadata projections](postgres_job_views.go) that omit execution payloads and project bounded result scalars before transfer, including Jobs that already retain whole snapshots. The existing Go decoder remains authoritative: malformed recognized values omit the result summary without failing the page. SQL preserves recognized case aliases and null/type behavior without unchecked numeric casts. This bounds transferred result bytes, not PostgreSQL work inspecting retained JSONB. Internal full reads, lease transitions, retries and retained rows are unchanged; no migration or grant change is needed.

Job units use the existing tenant command transaction for enqueue, deduplication, reads, cancellation and audit failures. A private lease-update `QueryRow` helper checks scoped and trailing arguments, returned Job handoff, missing-row conflict translation and failed reads without taking transaction ownership. Worker claim selection and actual lease fencing retain PostgreSQL coverage. Repeated running cancellation persists its returned timestamp, while terminal cancellation leaves retained state unchanged; the PostgreSQL lifecycle test checks repeated readback and lease preservation.

Lease updates and cancellation keep `updated_at` nondecreasing. Heartbeats retain the later existing/requested lease expiry, and waiting retries cannot precede the retained transition. Atomic SQL clamps do not alter the tenant/owner/expiry predicate. Deterministic PostgreSQL clock regressions cover backward-time success and negative lease controls; no migration or privilege change is required.

Automatic-source units cover candidate field mapping, interval/policy/limit bindings, read failures and row cleanup through a private `Query` helper. Scan failures discard candidates; iteration failures can return candidates with an error, which the maintainer rejects before creating work. Existing admission-helper units retain capacity, deduplication, timestamp and failure checks. PostgreSQL tests own due eligibility, deterministic revision jitter, ordering and query limits, database time, global admission locking and committed effects.

Housekeeping units cover constructors, input bounds, aggregate decoding, mark/delete sequencing, source-coordination allocation and optional semantic-reference selection through private transaction helpers. A narrow `BeginTx` dependency tests timeout setup, failure stops and withholding provisional progress after commit failure. Source coordination skips a zero-quota page so it cannot report saturation; the worker still uses its fixed batch of 100. Existing scripted fixtures establish Go decisions and query arguments, while the integration tests retain actual SQL eligibility, database time, locking, privileges, rollback and committed effects.

Operational diagnostics units in `operational_snapshot_test.go` exercise the complete collector through a private `QueryRow` boundary. Existing scripted rows check every aggregate's field mapping, UTC collection time and query arguments, preserved error causes, immediate failure stops and rejection of partially decoded results. The public wrapper still supplies the worker pool; no pool or SQL engine is simulated. `operational_snapshot_integration_test.go` and `operational_webhooks_integration_test.go` retain real PostgreSQL assertions for empty and cross-tenant worker aggregates, exact ages, eligibility boundaries and collection recovery.

Permission-failure cases revoke and restore individual columns only on fixture-owned worker roles. Existing notification lifecycle tests retain loss, retry and evidence-cleanup assertions. Run `make coverage-postgres-check` for the instrumented database suite; its coverage is separate from unit coverage.

The [database-role runbook](../../../documentation/src/content/docs/operations/database-roles.md) owns provisioning and migration ordering; [backup/restore](../../../documentation/src/content/docs/operations/backup-restore.mdx) and the linked repair runbooks own operator procedures. Do not use ad hoc SQL changes or automatic resets as an upgrade workflow.

Search consistency tests share the [Catalog lexical corpus](../../catalog/testdata/README.md) with Go scoring tests. Real PostgreSQL tests cover local and indexed matching, cursor traversal and the bounded migration-000027 projection repair without changing immutable evidence. The normalization tests check the frozen SQL Letter/Number class and every lowercase mapping against the pinned Go Unicode tables. A small SQL translation supplements the newer Go mappings absent from PostgreSQL 18's Unicode tables.

The semantic adapter bounds each write to 32 members, preserves the first vector for an input digest, separates Control/public disclosure keys and checks live Job ownership before and after writes. Completion checks enumerated membership and authoritative generation; reads check that generation again in their own snapshot. Admission declines a public scope whose snapshot is no longer active without interrupting reconciliation of remaining candidates. The bounded immutable-publication similarity helper admits at most 1,000 explicit keys; authenticated Search and local Explore instead select and match their eligible populations in SQL, with a 100,000-identity work ceiling and no entire-tenant hydration in Go. Query and document inference happen outside these repository transactions. `make migrate-semantic-plan` and `make migrate-semantic-apply` select the [optional schema](../../../migrations/semantic/README.md), without enabling inference or creating work.

`semantic_disclosure_integration_test.go` captures exact provider-port inputs after real SQL selection and indexing. Local released and approved indexed metadata, identifier fallback and active public entries have independent expected text. Retained raw documents, context/evidence markers, later private revisions, inactive publications and another tenant's publication are controls for unintended disclosure. The provider is inert; these tests qualify database selection, not model quality or provider retention. Existing embedding-client tests separately qualify prefixes, JSON serialization and endpoint credentials.

`semantic_test.go` and `postgres_semantic_*_test.go` use isolated inputs and the existing command coordinator for bounds, lease/generation checks, metadata projection, vector reuse, admission, result hydration and facet accounting. Due-candidate units use a private `Query` helper for control/public row mapping, profile/dimension/exclusion/limit binding and row cleanup. Scan failures discard candidates; iteration errors can accompany candidates, which the existing maintainer unit rejects before creating work. Cleanup units use scripted transactions and affected-row counts to check selection decisions, argument binding, member-plus-vector totals and failure stops without taking transaction ownership.

Transactional read fixtures request fresh read-only snapshots; write fixtures retain command ownership. They do not open pools or verify SQL eligibility, ranking, locking or vector arithmetic. The semantic integration tests retain those guarantees, including extension setup, exact runtime identities, RLS, immutable storage and cleanup. A competing cleanup transaction must cause zero removals, preserve generations, members and vectors, and leave no acquired worker-pool connection.

Bounded cleanup resumes after release while the current ready generation survives; query-plan runners remain explicitly selected. See [hybrid-search operations](../../../documentation/src/content/docs/operations/hybrid-search.mdx) for enablement and fallback.

Authorization qualification reuses the owned exact-login fixture in integration-tagged tests. [The fixture guide](../../../test/authorization/README.md) documents the historical SQL-only admission/snapshot trial and resolver/Search baseline. Those trials are separate from implemented ADR-0022 enforcement and do not qualify future production manifests. `make test-integration` executes and cleans the disposable environment.

The production authorization core lives in `postgres_authorization.go`. Migration 000034 introduced its retained policy and transaction boundaries. Current permission reads use compact membership IDs and coherent snapshots; write admission joins the existing command transaction and survives through response completion. Authority writers take an exclusive tenant fence before advisory/object locks and increment revisions atomically via invoker-only triggers.

An exact permission read selects the policy revision and ordered decision array in one SQL statement. Collection admission uses the same decision expression. Write admission still locks the tenant fence before a separate permission statement, so evaluation sees changes committed while the lock waits. Tenant context, current membership checks and privileges remain unchanged. This reduces network round trips without caching authority.

Collection predicates use a scalar subquery for the global permission value. PostgreSQL evaluates it once per statement, instead of parsing the same policy JSON for every candidate. Namespace checks select permitted namespaces through an uncorrelated subquery with the existing direct/group predicates. PostgreSQL can hash that selection rather than probe assignments for every candidate. Neither result is cached between statements or principals. Current policy, tenant isolation and selection before pagination remain unchanged.

Indexed Search uses `SET LOCAL jit=off` before indexed selection. Compilation of its many bounded provenance subplans can cost more than query execution. The setting ends on commit or rollback; it does not change server defaults or `plan_cache_mode`. Failure to set it stops selection. Real PostgreSQL tests verify restoration on the same pooled connection after both outcomes.

The exact manifest and restore inventories cover new tables, references and guards. `authorization_core_integration_test.go` qualifies these real boundaries separately from the historical SQL-only trial. Runtime authentication uses compact `ResolvePrincipal`; domain commands and replay use current action/scope admission. Bounded self projections and authorized collections query retained policy rather than hydrated Actor grants.

The historical hydrated resolver remains a comparison/test control, not runtime authority. The [authorization test guide](../../../test/authorization/README.md) describes integrated replica, cost and recovery checks.

`postgres_authorization_administration.go` owns bounded SQL pages, exact custom sets, same-realm groups/direct members and scoped assignments. Use [application context](../../../CONTEXT.md#postgresql-transactions-and-migrations) for the current format and manifest.

`authorization_administration_integration_test.go` uses real API privileges, RLS, schema guards, rollback, observed revocation blocking and restore checks; `postgres_authorization_administration_test.go` uses scripted rows for isolated projection/error handling only. The existing process fixture qualifies durable administration replay after restart and denial after revocation. Group membership is included in offboarding and restore integrity checks. Domain and collection enforcement is complete; no ordinary role-name check grants authority.

New assignment-API tests independently qualify final-administrator refusal, explicit handover, singular audit and bounded realm-private group paging.

Indexed Control declaration predicates use `search_license` and `search_categories` before counts, ranking and hydration in both lexical and hybrid SQL. Migration 000039 adds strict nullable projections and filter readiness version 1. Unavailable optional evidence does not make an observation incomplete; only outdated readiness needs bounded owner repair. The shared declaration corpus checks Go/SQL type, count, Unicode and normalization parity. Real PostgreSQL tests qualify alias ingestion, source grouping/conflicts, exact lookup, paging, role/RLS denial, retained-state upgrade, bounded repair, unchanged bytes/digests, restore drift and local precedence. Control Search and browser filters apply across selected origins; namespace filters and Control Explore remain local-only.

Lexical and hybrid indexed results return the same presentation source ID, source revision and presentation generation. Selection uses the first matching source ID for the chosen entry digest within the current tenant and eligible contribution set. Real PostgreSQL tests compare both projections, including identical-byte contributors and conflicting sources. Local results do not gain indexed-source evidence. This read projection requires no migration or additional privilege.

Tenant operational settings use a forced-RLS singleton, exact API write/worker read grants and tenant advisory fences. Save/reset advances its revision with required audit evidence; no settings deletion or public notification is allowed. New default-budget admissions read after the shared fence. Explicit Job budgets and deduplicated work stay unchanged. See [ADR-0025](../../../documentation/src/content/docs/architecture/decisions/0025-tenant-operational-settings.md) and `tenant_settings_integration_test.go` for the real boundary.

Creator/reviewer admission resolves exact immutable Resource creation/adoption or review-submission audit attribution with at most two rows. Its partial audit index and same-tenant membership primary-key join keep the lookup bounded; missing, duplicate or malformed bindings refuse creator/reviewer authority. Public attribution fields stay unchanged. Group archival checks both active assignments and member relations, with the same prerequisite enforced by the forward-only SQL guard. Existing archived history is never rewritten.

Development owner provisioning carries exact namespace grants in the same principal transaction as membership, global assignments and attributed evidence. Missing/foreign namespaces fail without partial authority; no namespace is created or grant widened. Active references are reused; explicit configured regrants preserve revoked history and restore namespace membership without backdating it. Other retained grants remain unchanged. No schema or privilege-manifest change is needed. Isolated planning/failure tests are separate from the real PostgreSQL and compiled-owner-command qualification.

Access directories apply exact subject/name, lifecycle/type and realm predicates before SQL limits. Member contributions select bounded assignment IDs before loading role, group and latest relation metadata in one policy-bound read. Foreign-realm group coverage remains unavailable; tenant-wide direct inventory and current-realm group administration keep their separate boundaries. This adds no schema object or runtime privilege.

Self-assignment group captions hydrate only distinct group IDs from the selected page, with explicit tenant/current-realm predicates and the page limit in the same coherent authorization read. Missing or failed caption rows fail closed. No schema or privilege-manifest change is needed.
