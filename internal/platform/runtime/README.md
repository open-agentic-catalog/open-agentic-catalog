# Service composition

[runtime.go](runtime.go) verifies embedded profiles, loads role-specific configuration, validates injected inputs and wires domain services to infrastructure adapters. The selected API, worker or memory-only combined role determines which services and listeners exist. The command layer owns starting listeners, supervision and graceful drain.

[external_representation.go](external_representation.go) adapts domain inspection requests to the hardened outbound router. It preserves exact Plugin archive encoding, binds retrieval to the current policy, rejects origin changes and copies the resulting bytes and provenance into domain values.

[semantic.go](semantic.go) connects optional metadata indexing to existing leased Jobs and bounded generation cleanup. The API owns query inference; workers own batches. Disabled mode constructs neither client nor maintainer. See [hybrid search operations](../../../documentation/src/content/docs/operations/hybrid-search.mdx) for profile, disclosure and fallback boundaries.

Runtime construction must not acquire migration authority or silently enable an unavailable provider. Tracing starts only when explicitly requested by `catalogd`; operator inspection does not create an exporter. Stop request producers and drain tracing before `Runtime.Close` releases shared resources.

[Policy projection units](policy_projection_test.go) cover enabled discovery host/tenant/audience bindings and independent webhook topology, HTTPS-only limits, copied inputs and conversion failures. They call private projections with local values, without constructing the runtime. Configuration tests retain host and policy validation; functional tests retain publication and sender construction, disabled-policy dependency handling, provider cleanup and transport enforcement.

Colocated unit tests cover early configuration rejection, fake job/lifecycle ports and static architecture/documentation contracts. [Composition helper tests](composition_helpers_test.go) verify capability state, atomic identity-evidence projection and role-specific startup state when the existing tracing callback fails before dependencies are constructed. Concrete resource cleanup and complete service composition retain their functional tests. Run `go test ./internal/platform/runtime -shuffle=on -count=1` from the repository root. Add `-tags=functional` for application composition, trust/listener fixtures and Make subprocess contracts, then run the applicable gates in [CONTRIBUTING.md](../../../CONTRIBUTING.md). The [platform overview](../README.md) maps the concrete adapters.

The optional [development demo archive route](../../../documentation/src/content/docs/reference/configuration.mdx#development-demo-archives) wraps only external representation fetching. It binds one literal private/loopback HTTPS origin, loaded trust and strict prepared Plugin ZIP paths/digests/sizes to the fixed development tenant. The runtime consumes only the nonsecret allowlist; it has no dependency on the sample inventory. Disabled deployments keep the ordinary router unchanged; production/OIDC configuration is rejected. The fixture is not federation authority and never resolves credentials. `demo_archives_test.go` checks admission/evidence with controlled ports; `demo_archives_functional_test.go` separately verifies real TLS, failure handling and actual runtime inspection.
