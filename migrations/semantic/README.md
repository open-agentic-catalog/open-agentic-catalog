# Optional semantic schema

This immutable SQL is embedded with the core migration bundle but is not a core numbered migration. `catalogctl migrate plan --semantic` inspects the optional setup; `catalogctl migrate apply --semantic` applies it under the same schema-owner advisory lock as core migrations and exact-role reconciliation. The administrator must first install pgvector 0.8.7 in an application-visible schema. DDL uses that schema's qualified vector type and functions. Ordinary core migrations never require the extension. The optional schema has its own checked version/checksum row; changing applied SQL is rejected.

For an existing extension, drain the API and worker first. Ask the database administrator to run `ALTER EXTENSION vector UPDATE TO '0.8.7'` before semantic setup. Installing updated extension files does not update an existing database's extension. Catalog commands do not upgrade pgvector or rewrite the applied semantic schema.

The corresponding Make targets are `make migrate-semantic-plan` and `make migrate-semantic-apply`. They use the existing `CATALOG_MIGRATION_DATABASE_DSN`, `CATALOG_POSTGRES_CONFIG_FILE`, `CATALOG_DATABASE_API_ROLE` and `CATALOG_DATABASE_WORKER_ROLE` inputs. Runtime credentials must not be used for these operations.

The tables contain rebuildable, tenant-scoped vectors and generation membership, not authoritative Catalog documents. Generation identities reference the existing durable Job. Runtime grants remain column-explicit: API reads, worker derived-state writes, no runtime DDL. Public and Control vectors have separate disclosure keys. Repository writes must verify the Job lease and immutable input identity; query callers must reapply current visibility and source eligibility.

Setup does not enable semantic search, create indexing Jobs or contact a model. After setup, configure the API and worker with matching enabled settings following [hybrid-search operations](../../documentation/src/content/docs/operations/hybrid-search.mdx). Core deployments do not need this setup. Retain optional tables when disabling the capability; do not delete authoritative data or modify applied SQL to reset derived state. If setup commits but grant reconciliation fails, keep runtimes stopped, correct the reported role/grant problem and rerun the same apply command. Run `make test-integration` for disposable installation, repeat apply, exact grants, lease/profile fencing, RLS and vector-storage checks.
